## 1. 一页结论

**推荐方向：V1的空间规则 + refined的轻量视觉层级 + compact的对象详情连续性。**

解决“有的拥挤、有的空”依靠任务空间分配，不依靠缩字、裁内容、删字段或把白面板撑到屏底。本轮只收敛一套推荐方案，不提供多个主题让用户重新选。

| 方面 | 推荐决定 |
| --- | --- |
| 导航与工具 | 保留全局侧栏、唯一账号／版本／退出、申报／验收／库存三入口；业务页签用下划线，模块工具与本页动作明确分区，不再出现相邻且无法辨认作用的两个更多 |
| 列表 | 占满可用宽度，短字段语义定宽、名称规格吸收余宽；少量记录自然结束，分页紧随结果，不把空白锁进一张大卡片 |
| 验收 | 按需切单、全宽编辑；数量、实付总额、申报与实收厂家、位置常驻；历史和到货资料分区，不恢复常驻选单双栏 |
| 详情与短表单 | 同一物资身份和范围持续可见，详情／批次／流水局部切换，必要时保留原三级返回；详情无框分组，短表单保持760px |
| 手机与低高度 | 手机抽屉导航、同DOM卡片／验收网格；不隐藏唯一功能入口；长错误、末字段、保存、取消和切单可达 |
| 反馈 | 先保证校验、冲突、提交中、结果待确认和成功互不矛盾，再统一跨模块状态与日期标签 |

第一批范围仍以物资及其共享工作区为主。其他模块只跟随已确认的共享规则；不借本轮重做所有业务页面、增加仪表盘或更换框架。

## 4. 页面与空间规则

### 4.1 页头、页签和工具

推荐结构：

```text
唯一全局头：模块名／当前位置                         账号 · 版本 · 退出
业务页签：申报 | 验收 | 库存                         设置图标 · 物资工具
本页标题 · 结果数                                    本页主要动作
搜索 · 查询 · 高级筛选                               当前条件／清除
结果表或办理区
分页或本次提交区
```

“物资工具”承载扫码、说明等模块能力；导出、模板等本页低频动作归本页工具区。图标按钮有可访问名称和悬停提示，不能把所有功能继续放进两个相邻的无差别省略号。手机转为单个可展开工具入口，不能直接display:none删除唯一入口。

页标题和主要动作在同一行。标准桌面筛选默认一行，只在用户展开高级条件或长错误时增加高度。不要为了强求一行而挤掉文字、强缩输入或侵占账号栏。

### 4.2 列表与长文本

- 继续点名表格的语义列宽，短字段保持合理下限，名称／规格分配余宽。不得把固定列宽、首列百分比或末列操作宽度全局套到所有表。
- 标题／名称14px主显，编号12px次显；完整编号可查看／复制，不能只用无入口的省略号隐藏。
- 桌面数字右对齐、等宽数字，手机左对齐。日期允许在日期与时间之间有控制地换行，不跨入状态列。
- 少量结果自然结束，计数／分页紧跟最后记录。不强撑空表体、插空行、加统计大卡片或删除空列来“填满屏幕”。
- 长备注、用途等点名字段可采用约3行摘要＋明确的全文展开／详情入口；名称不全站统一截断。键盘和手机均能查看全文，打印与导出保留原文。
- 名称、编码和本行操作相邻，不以`margin-top:auto`等方式把动作推到长行底部，造成同一格中间大片空白。

### 4.3 验收

继续使用“当前单摘要＋切单 → 办理／历史／清单 → 全宽验收行 → 本次选择与提交”。

正式八列及其信息不删：选择、名称／规格、申报／已验／结案／剩余、本次合格、实付总额、厂家／位置、状态、操作。厂家申报值、实收值和位置可分组对齐，但常驻核对，不为了表面紧凑全部藏入差异区。

批号、效期、拒收原因等低频项原位展开，开关始终在主行且有展开状态。常规1366宽度优先编辑空间，不常驻220／272px选单栏；即使1920宽也不自动恢复永久双栏。本轮不增加特宽屏布局开关。

实付总额仍是本次合格品含税总额，不改成单价。数量显示对应单位，不将不同单位直接相加成一个无单位“合格合计”。选择计数、金额和提交状态由真实数据更新，已验收行不以勾选框假装本次已选。

底部提交区仅服务验收，不泛化成所有列表的固定屏底栏。长错误和低高度下应明确滚动边界、可滚到末字段，不能以overflow:hidden裁掉提交区。

### 4.4 详情、短表单和设置

详情保留物资名称、编码和当前范围。库存详情以“基本信息／批次与单件／来源流水”少量局部分区组织；具体单件或原始事件仍可沿原返回栈打开，不套多层页签。切换及返回保留查询、分页、条数、范围和焦点，不能重新按当前可见行计算全局合计。

详情以无框信息网格和小标题分组，不把每个字段做成卡片。短表单最大760px，详情最大1120px，设置最大1040px、局部导航176px；宽屏侧边留白是有意保留的阅读空间。

名称、规格、备注可占整行，数量／金额／日期／单位按语义给宽度，不把所有输入等分。系统编号只读；已引用单位和管理方式的只读规则继续保留。复杂明细、扫码、标签校准继续原专门工作区，不强塞进短表单。

## 5. 字号、视觉与响应式

| 项目 | 统一规则 |
| --- | --- |
| 字号 | 页标题22px、区块18px、正文14px、标签／表头13px、说明12px；11px只沿用现行明确白名单，不扩到表头、字段和办理说明 |
| 间距 | 桌面正文20px、手机12px；同组8px、组内12至16px、分组24px；长值自然增高，不能强固定行高裁切 |
| 控件 | 桌面基础36px，手机触控至少44px；手机输入保留现有16px特例，不为统一正文而缩小 |
| 表面 | 页面分区不做浮动大卡片，不套卡片；保留细网格及必要竖线，减少装饰边框／阴影，不能未经施工卡直接抹去所有竖线 |
| 颜色 | 保留现有令牌；普通文本中性、链接与当前项用主色。状态文字常驻，待确认不能画成已失败或已成功；未知自由状态中性回退 |
| 图标 | 复用现有Lucide白名单，工具用熟悉图标及名称提示，不增加任意SVG、外网图标字体或新依赖 |
| 侧栏 | 延续245px／72px既有断点策略，手机为抽屉；不采用refined手机仍常驻64px图标栏 |
| 手机表格 | 同一DOM的记录卡片，360至767短字段两列、极窄再单列；库存名称优先、数量单位随后，原七列和打印顺序不动 |
| 验收窄屏 | 沿用1100px及以下的同DOM多行编辑网格；标签、切单、错误和提交都可达，不退回600px手机宽表 |
| 低高度 | 主区可收缩、内容有明确可滚动容器；不能只证明document无溢出，还要检查工作区是否被撑宽或裁切 |

所有视觉顺序变化都需验证Tab焦点与阅读关系，不把“同DOM”当成原生读屏已经验收。字号不随视口宽度缩放，字距保持0。

## 6. 必须保留的合同

权限和所有原入口保留；唯一全局账号／版本／真实退出保留。草稿离开保护、提交忙态、未知结果保护、同正文与同幂等键重试、冲突后核对、焦点恢复和三级返回不可为了视觉简化删除。

库存全局合计与本行／批次数量分开；库存七列及打印全文、固定修订原单二维码、历次到货及同次资料版本、资料上传不重复入库等合同不变。后端事务、备份、数据库、标签校准和CSV／Excel语义不在本轮改动范围。

通用非幂等新增的未知结果恢复需要单独核对调用链，不能仅改成“请重试”就宣称安全，也不能声称前端改了文案即补全服务端幂等。

明确不采用：新主题／组件库、密度切换器、永久验收双栏、六入口恢复、按屏高自动改变普通物资分页、全站固定表格列宽、自动删空列、全站两行截断、手机隐藏功能入口、每字段卡片和填空式仪表盘。
