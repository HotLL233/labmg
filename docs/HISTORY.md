# 开发历程

本文件按时间记录项目的重要需求、决策、实施与验证结果。后续继续追加；版本更新说明统一维护在 [CHANGELOG.md](CHANGELOG.md)，开发操作约定见 [DEVELOPMENT.md](DEVELOPMENT.md)。计划与未解决问题不代表已经实现。

## 2026-10-16

### 1. 初始目录与代码分析

- 项目最初位于 `C:\labmg`，使用 Node.js 内置 HTTP、同步 SQLite 和静态 HTML/CSS/JavaScript，业务包括档案、模板、财务、设备、物资、体系文件、人员和合同管理。
- 最初源码入口为根目录 `server.js`，页面位于 `public/`；本地数据库、附件、日志和部署产物混放在项目根目录附近。已有 `.git`，但尚无提交，也未配置远程仓库。
- 完成了目录、配置和源码的静态分析。确认 SQL 主要使用参数绑定，业务数据集中保存在通用 `records` 表及 JSON 扩展字段中；当前应用未接入 Docker 配置中的 PostgreSQL、MinIO。
- 发现的问题包括：明文密码和备份中的凭据、退出登录未完整撤销会话、记录分区权限与附件/导出等接口授权不一致、启动时删除旧 `samples` 数据，以及备份恢复不等于完整灾备。同步数据库/文件操作、全量读取和整条记录覆盖更新，也需要在多人使用前验证与改进。
- 上述安全与业务问题来自静态分析，目录整理没有修复它们，也没有因此获得并发容量结论。
- 前端另通过 Node VM 与伪 DOM 复现公共页面状态脱节，以及设备阶段中英文值比较错误；设备附件逐条串行请求和重复全局函数覆盖也被列为后续维护事项。这些发现不等于真实浏览器验收。

### 2. 明确开发目标与顺序

- 用户明确目标：约 10–30 名用户、不同角色权限、简洁页面，以及多人同时操作时的可靠性。
- 决策是继续基于现有项目开发，先补齐后端权限、会话及数据完整性，再简化页面，并用实际业务压测验证容量；暂不进行全面技术栈重写。
- 多账号、多人在线与高写入并发分别考虑。SQLite 先保留，不能仅凭在线人数承诺容量；出现持续写锁、响应时间不达标，或需要多实例/多机数据库时再评估 PostgreSQL。迁库也不能代替同步文件操作和全量导出的改进。
- 待实施的验证包括角色/API 越权负向测试、双用户编辑冲突、库存与收支等业务事务一致性，以及查询/保存/上传/导出混合负载下的响应时间、错误率、内存与写锁情况。
