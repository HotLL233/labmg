# 物资模块需求确认与改造方案

日期：2026-10-22。基线：`0.9.4`／`28ce719`。
来源：本会话三轮问答（12 个问题）的你的原话 + 源码核查。
**边界**：未启动服务、未跑测试、未连接数据库、未操作 NAS。下文"现状"指源码字面实现；标「假设」的是推断，需要实测或样本才能确认。

---

## 0. 结论先行

1. **性能不是这轮的主矛盾。** 记录 1 万条以内、20–30 人，`records` 全表扫只有毫秒级影响。索引、压缩、缓存降级为顺手做，不占主线。
2. **你的三条主诉（找不到东西 / 操作太重 / 期初与明细繁琐）本质是信息架构和表单效率问题，不是后端能力缺失。**
3. **你点名的一部分需求已经在跑，重复开发会白干。** 申报的"权限人提交"、领用审批状态机、扫码带出物资信息，三项均已实现（证据见第 2 节）。
4. **真正缺的是四件事**：批量录入的可靠性、单行修正的入口、批次效期的闭环（临期/过期/FEFO）、待办与状态的可见性。

## 2. 已有能力核查（避免重复开发）

| 能力 | 证据 | 现状边界 |
| --- | --- | --- |
| 草稿多人协作、权限人提交 | `materials.js:260,275,318` | 任何人可建单/加行，只有 `MATERIAL` 角色 + `materials.request.submit` 能提交；提交后改稿另需 `edit_submitted` |
| 提交后受控修订 | `schema.js:104-109` + `materials.js:369` | 每次修订存前后快照 + 原因，`revision` 递增 |
| 领用审批 | `materials.js:1493` | 申请 → `issued`/`rejected`/`cancelled`，由 `materials.issue.write` 执行 |
| 分批验收/拒收/结案/冲正 | `schema.js:110-124` | 数量按 `qty_m`、金额按 `amount_cents` 整数记账，冲正唯一且只能一次 |
| 扫码解码 | `material-scan.js` + `zxing-wasm` | 摄像头 + 图片文件双通道，本地解码不上传 |
| 批次/效期字段 | `schema.js` 多处 `batch`/`expiry_date` | **仅存储，无任何临期判断、无 FEFO、无过期拦截** |
| 窄屏布局 | `tests/mobile-layout.test.js` | 导航和长弹窗可用，不是扫码专用界面 |

**结论**：后端业务能力比你以为的完整。要改的是"入口、密度、反馈"，不是重写流程。

## 3. 缺口与改造设计

### 3.1 期初库存与物资主档（你的最大痛点）

现状：模板 11 列，区域/仓库/批号/有效期/存放位置全部参与校验；导入器是自己写的 ZIP 目录解析，主动拒绝 `customXml`、`connections.xml`、外部链接、公式、128 个以上压缩条目（`material-xlsx.js:31-60`）。报错会列出最多 200 条并带工作表/行/列（`material.js:29`），但**不给可回填的文件**。

设计：

| 改动 | 做法 | 风险 |
| --- | --- | --- |
| 模板分必填/选填 | 必填收敛为 `名称/规格/单位/数量`；区域、仓库取单据头默认值；批号/效期/位置允许空，标"后补" | 低（后端 `openingItemInput` 已接受空批号/位置） |
| 导入容错 | 白名单放行 `customXml/docProps/theme` 等无害部件；对文件体积/条目上限给明确提示而不是笼统结构错误 | 中（安全校验不能放宽到允许外部链接/宏） |
| 失败可回填 | 导入失败时用现成 `write-excel-file` 生成"带错误列的原表"下载，用户改完直接再传 | 低 |
| 行内编辑 | 期初明细列表加行内编辑/删除（后端 `PUT/DELETE /openings/:id/items/:itemId` 已有，只缺前端） | 低 |
| 单据克隆 | "从上次期初/同类单据复制明细" 生成新草稿 | 低 |

**假设待验证**：你说"Excel 导入总出问题"，最可能是 WPS/Office 另存的正常文件被白名单误拦。请给我一个曾经失败的样本（可脱敏），我按真实部件判定，而不是继续猜。

### 3.2 申报

- 列表补三列：**提交人 / 提交时间 / 验收进度**（数据现成，`schema.js:87-94`）。
- 加"退回草稿"（`MATERIAL` 权限），让填错的人在原单上改，不用重开。
- 加"从历史单复制"和"常用清单"，对应你说的"找物资省事"。
- 分类目录树浏览（现只有关键词搜索 + 下拉）。

### 3.3 验收入库

- 列表多选 + 批量验收：同一批次到货的多个申报行，一次填数量与总金额。
- 验收页默认按"待验收"排序，先进先处理。
- 差缺结案时给明确提示（现需人工判断剩余量）。

### 3.4 领用（无配额）

- 两个标签页：**我的申请** / **待我审批**（`viewAllIssues` 已有）。
- 驳回原因在申请人侧必须可见（数据已有 `reason`）。
- 发放时按批次列表选择，默认按效期升序（见 3.5）。
- 明确不做：配额、限额、超限审批。

### 3.5 批次效期闭环

| 改动 | 做法 | 数据模型 |
| --- | --- | --- |
| 临期预警 | `material_state` 存阈值（默认 30/60/90 天），库存页与工作台出清单 | 只加配置行，不改表 |
| FEFO | 发放候选按 `expiry_date` 升序，空效期排最后 | 排序逻辑 |
| 过期拦截 | 过期批次发放需填写原因才放行（软拦截），不硬性拒绝 | 复用 `reason` 字段 |

### 3.6 扫码端（手机只扫码）

现状：扫完直接问"入库还是领用"（`material.js:112,292`）。

改为**扫码结果卡片**：
```
[物资名称] [编码] [规格] [单位]
库存：3 个批次 / 合计 12.5 | 最近效期 2027-03-01
[查看库存与批次]  [入库]  [领用]
```
- 手机端进 `/scan` 的精简路由：只有扫码框 + 结果卡片，不加载列表页。
- 硬前提：HTTPS + 客户端信任本实例 CA（0.9.4 已具备自动 HTTPS）。

### 3.7 信息架构

物资页从"5 个并列页签"改为四组：

| 组 | 内容 |
| --- | --- |
| 我的待办 | 待我审批的领用、待我验收的申报行、临期预警 |
| 库存 | 台账、批次明细、期初、调整、盘点（后续） |
| 申请 | 申报单、领用申请（我的/全部） |
| 主数据 | 分类、区域、物资信息库、条码、标签模板 |

搜索框提到页面级，一次搜物资编码/名称/单号。

## 6. 需要你拍板的四件事

1. **期初模板必填收敛到几列？** 我建议 `名称/规格/单位/数量` 四项，区域和仓库取单据头默认值——你的实际填表习惯是否接受？
2. **过期批次能不能放行？** 我建议软拦截（填原因可放行），因为实验室常有"过期但仅作对照"的用法；你要硬拦也可以。
3. **"待我审批"的审批人是 `MATERIAL` 角色全体，还是按区域/部门拆？** 现在只有角色维度，拆部门要加字段。
4. **手机扫码要不要独立页面？** 独立精简路由体验最好，但要多维护一套页面；不做就用现有响应式。

另外：**给一个失败的 Excel 样本**（可脱敏），我把 3.1 的"假设"变成确定结论，否则导入改造就是盲改。

## 7. 与性能方案的关系

`docs/OPTIMIZATION_PLAN.md` 里的 P1（索引/压缩/缓存/安全补丁）与本方案不冲突，但优先级降到"顺手做"；P2 的结构改造（路由表化、批量取数、前端 ESM）应当**跟着本方案的功能改造一起做**，而不是单独做一轮重构——反正这些文件都要改，一次改到位比改两遍省事。
