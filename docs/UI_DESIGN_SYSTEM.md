# LabOS 界面设计方案（UI 2.0）

> 状态：设计确认稿，未改任何现有代码。
> 依据：`src/public/styles.css`、`material.css`、`material-scan.css`、`index.html`、`app.js`、`material.js` 的现状核查；业务需求见 `docs/优化方案.md`（R1–R14）。
> 配套可交互原型：`docs/prototypes/ui-redesign.html`（可直接双击打开，含 6 个界面）。

## 0. 设计判断（先给结论）

**现有界面不缺美化，缺的是三样结构性的东西。**

| # | 问题 | 可测量的事实 | 后果 |
| --- | --- | --- | --- |
| 1 | **三层导航叠加** | 侧栏 13 项（`app.js:1` 的 `M`）+ 物资页签 5 项（`material.js:39` 的 `mw-nav`）+ 页头并列动作 5–6 个（扫码入库/扫码领用/标签模板/分类区域信息库/原台账） | 用户进入物资模块后，一屏内有 3 套导航争夺注意力，没有"我现在在哪、下一步去哪" |
| 2 | **单元格内堆叠三段信息** | 验收表 `material.js:43`：一格塞 `<strong>名称</strong>` + `编码 · 分类` + `<br>区域 · 仓库`，共 4 个数据点/格；`material.css` 里 `small` 只有 **11px** | 一行扫读要四次视线换行，验收 20 行就要看 80 段文字 |
| 3 | **没有"待办"概念** | 全站无"待我审批/待我验收"入口；打开即落到工作台总览数字 | 用户每天第一件事是翻页签找活干，而不是看到"今天要做什么" |

**还有四个次要但影响手感的点**：字号挤在 11–14px（桌面场景偏小）；一个蓝承担主色/激活/链接/焦点四种语义；状态只有文字没有色彩编码；图标是 Unicode 字符（`▦▤▧￥◈◇`），字重与基线不统一。

**设计方向**：不推翻品牌（深 navy 侧栏 + 蓝主色保留，用户已形成肌肉记忆），重做**层级、密度、状态编码**三件事。

## 1. 设计原则

| 原则 | 具体含义 | 反面（现有实现里的例子） |
| --- | --- | --- |
| **一眼看到活** | 首屏第一块是"待办"，不是统计数字 | 工作台先给总量/收支，待办要自己找 |
| **一格一件事** | 表格单元格只放一个语义单位，次要信息降级为行内注释或折叠 | 名称/编码/分类/区域/仓库挤一格 |
| **状态三重编码** | 颜色 + 形状（圆点/胶囊）+ 文字，不只靠颜色 | 五种验收状态全靠文字 |
| **手不离键盘** | 录入场景全键盘可达；Tab 顺序符合阅读顺序；焦点环 2px 清晰可见 | 焦点环有，但跳转顺序随 DOM 决定 |
| **数字可对齐** | 所有数量/金额用 `tabular-nums` 右对齐 | 数量在表格里左对齐，位数不同扫不出量级 |
| **打印是刚需** | 单据与标签的打印样式与屏幕一致，不丢列、不截断 | 现仅 `@media print` 放开 `dialog` 高度 |
| **不做无意义动效** | 只保留 120ms/180ms 的状态过渡；尊重 `prefers-reduced-motion` | — |

## 2. 设计令牌（Design Tokens）

落地方式：新增 `src/public/tokens.css`，`index.html` 里在 `styles.css` 之前引入。**旧变量全部保留**（`--navy`/`--blue`/`--bg`/`--line`/`--text`/`--muted`/`--green`/`--red`），值映射到新阶梯，保证旧样式不改也能视觉收敛。

### 2.1 色彩

**主色（蓝）** —— 沿用现有 `#2c6df6` 作为 500，上下补齐阶梯：

| Token | 值 | 用途 |
| --- | --- | --- |
| `--c-primary-50` | `#eff5ff` | 选中行背景、信息底色 |
| `--c-primary-100` | `#dbe8fe` | 标签底、hover 底 |
| `--c-primary-200` | `#bfd7fe` | 描边 |
| `--c-primary-500` | `#2c6df6` | 主按钮、激活态、链接（**白字对比度 4.69:1，过 WCAG AA**） |
| `--c-primary-600` | `#1d56db` | 主按钮 hover |
| `--c-primary-700` | `#1a44b0` | 主按钮 active |

**中性（冷灰，与 navy 侧栏同调）**：

| Token | 值 | 用途 |
| --- | --- | --- |
| `--c-surface` | `#ffffff` | 卡片/面板 |

| `--c-text-4` | `#9aa8bc` | 占位/禁用（不用于正文） |
| `--c-nav` | `#14263d` | 侧栏（沿用 `--navy`） |

**语义色** —— 每种给出「文字色 / 底色 / 描边」三件套，保证在浅底上 ≥4.5:1：

| 语义 | 文字 | 底 | 描边 | 用于 |
| --- | --- | --- | --- | --- |
| success | `#0b6b47` | `#e8f5ee` | `#b7e0cb` | 已验收、已发放、库存充足 |
| warning | `#96540a` | `#fdf4e5` | `#f2d7ac` | 部分验收、临期、待完善信息 |
| danger | `#b42318` | `#fdecea` | `#f5c2bd` | 拒绝、过期、库存为负、危险操作 |
| info | `#1a44b0` | `#eff5ff` | `#c9dafa` | 已提交、待处理、中性提示 |
| neutral | `#55637a` | `#f0f3f8` | `#dde4ee` | 草稿、已取消、只读 |

### 2.2 字体与字号

字体栈保持系统字体（**不引入 Web Font**，符合零外部依赖的交付特征）：

```css
--font-sans: "Microsoft YaHei", "PingFang SC", "Segoe UI", system-ui, sans-serif;
--font-num: ui-monospace, "Cascadia Mono", Consolas, monospace; /* 仅单号/编码 */
```

| Token | 字号/行高 | 字重 | 用途 | 相对现状 |
| --- | --- | --- | --- | --- |
| `--fs-display` | 28/36 | 700 | 登录页、空状态主标题 | 新增 |
| `--fs-h1` | 22/30 | 600 | 页面标题（`mw-head h2`） | 24→22，字重 500→600 |
| `--fs-h2` | 18/26 | 600 | 面板标题（`mw-panel-top h3`） | 17→18 |
| `--fs-h3` | 15/22 | 600 | 区块/卡片标题 | 新增 |
| `--fs-body` | 14/22 | 400 | 正文、表格主字段 | 保持 |
| `--fs-body-strong` | 14/22 | 600 | 表格首列、关键值 | 13→14 |
| `--fs-label` | 13/18 | 500 | 表单标签、工具栏标签 | 11→13（**关键提升**） |
| `--fs-caption` | 12/17 | 400 | 次要说明（表格第二行） | 11→12（**关键提升**） |
| `--fs-micro` | 11/16 | 500 | 仅用于徽章内文字 | 保持 |

**为什么把 label 从 11 提到 13**：`material.css` 的工具栏标签是 11px，而同一行的输入框是 12px、页面标题 24px，中间断层 13px。实验室显示器常见 1920×1080，11px 中文在小字号下笔画粘连。13px 是中文标签的可读下限。

### 2.3 间距、圆角、层次

```css
/* 间距：4px 基准 */
--sp-1: 4px;  --sp-2: 8px;  --sp-3: 12px; --sp-4: 16px;
--sp-5: 20px; --sp-6: 24px; --sp-8: 32px; --sp-10: 40px; --sp-12: 48px;

/* 圆角 */
--r-sm: 6px;   /* 徽章、小控件 */
--r-md: 8px;   /* 按钮、输入框 */
--r-lg: 12px;  /* 卡片、面板 */
--r-xl: 16px;  /* 对话框 */

/* 层次：靠描边与底色，不靠重阴影 */
--shadow-panel: 0 1px 2px rgb(25 37 55 / .04);
--shadow-pop: 0 8px 24px -6px rgb(25 37 55 / .16), 0 2px 6px rgb(25 37 55 / .06);
--shadow-focus: 0 0 0 3px rgb(44 109 246 / .22);
```

### 2.4 图标

**替换 Unicode 字符为内联 SVG 线性图标**（1.75px 描边、`currentColor`、`stroke-linecap:round`），尺寸 18px（侧栏）/ 16px（按钮内）/ 20px（页头）。

理由：`▦▤▧￥◈◇✓⌘♙⇩⚙⌫◎` 来自不同 Unicode 区块，字体渲染后的字重、基线、视觉中心都不一致，在密集侧栏里看起来"跳动"。SVG 可统一控制，且不增加请求（内联在 JS 模板里）。

图标清单（新增 12 个，与现有菜单一一对应）：工作台 dashboard、资料档案 folder、电子模板 template、收支管理 wallet、设备管理 device、物资管理 box、体系文件 shield-check、委托合同 handshake、人员管理 users、导出备份 download、管理 settings、回收站 trash、审计日志 clipboard-list。

## 3. 信息架构重组

### 3.1 顶层：侧栏分组（13 项 → 3 组）

现侧栏 13 项平铺，无分组。改为三组，组间用 11px 小标题分隔：

| 组 | 项目 |
| --- | --- |
| （无标题，顶部） | 工作台 |
| **业务** | 资料档案、电子模板、收支管理、设备管理、物资管理、体系文件、委托单位与合同、人员管理 |
| **系统** | 导出与备份、管理、回收站、审计日志 |

行为准则：**分组只做视觉分隔，不改权限逻辑**（`canOpen` 不动），避免一次改动牵连 RBAC。

### 3.2 物资模块内部：三层收成两层

现状三层：侧栏 → `mw-nav` 5 个页签 → 页头 5–6 个并列动作。

改为：

| 层 | 内容 | 形态 |
| --- | --- | --- |
| 第 1 层 | 申报 / 验收 / 库存 / 领用 / 期初 · 原台账（收进"更多"） | 分段控件（segmented），带待办数字角标 |
| 第 2 层 | 「扫码入库」「＋新建申报」「导出」等与当前页强相关的动作 | 页面级主/次按钮，最多 2 个主按钮 + 1 个"更多" |
| 全局动作 | 标签模板、分类与物资信息库、原台账 | 收进页头右侧「⋯ 更多」下拉 |

**待办角标规则**：`验收` 显示待验收明细数，`领用` 显示待我审批数（仅对 `issue.write` 与 `acceptance.write` 角色显示）。为 0 不显示，避免视觉噪音。

### 3.3 新增：工作台"待办优先"

工作台首屏第一块改为「今天要处理」，四张待办卡：

| 卡片 | 数据来源 | 点击去向 |
| --- | --- | --- |
| 待我验收 · N 项 | `/acceptance?status=open` | 验收页 |
| 待我审批领用 · N 单 | `/issues?status=pending` | 领用页 |
| 未匹配物资信息的明细 · N 项 | 申报明细 `catalog_id IS NULL` | 申报列表（筛"待完善"） |
| 临期批次 · N 批 | 效期阈值（批次 F 实现后） | 库存页（筛临期） |

原统计数字（总量/收支/预警）下移为第二块，改为紧凑指标条。

## 4. 组件规范

### 4.1 按钮

| 类型 | 样式 | 尺寸 | 用于 |
| --- | --- | --- | --- |
| 主按钮 | 蓝底白字 | 36px 高 / `0 15px` / 13px 500 | 每屏最多 1 个（提交、保存、确认验收） |
| 次按钮 | 白底 + 1px `--c-line` 描边 | 36px | 次要动作 |
| 幽灵按钮 | 透明底 + 蓝字 | 32px | 行内"记录""原单""编辑" |
| 危险按钮 | 白底红字红描边，hover 红底白字 | 36px | 删除、冲正 |
| 图标按钮 | 32×32，仅图标 + `aria-label` | 32px | 关闭、更多、刷新 |

统一要求：`:focus-visible` → `outline: 2px solid var(--c-primary-500); outline-offset: 2px`；`:disabled` → `opacity:.45; cursor:not-allowed`；移动端最小 44×44。

**改动理由**：现有按钮字号 12px（`material.css` `.mw button{font-size:12px}`），与 14px 正文不协调；且主/次/幽灵/危险四类在旧样式里靠 `primary`/`ghost`/`mw-link` 三种类名混用，危险动作没有统一样式。

### 4.2 表单

- 标签在上、输入在下，间距 6px；标签 13px/500，必填加红色 `*`（`aria-required` 同步）。
- 输入高 36px（桌面）/ 44px（移动），`--r-md` 圆角，`1px solid var(--c-line)`。
- 聚焦：`border-color: var(--c-primary-500)` + `--shadow-focus`。
- 错误：输入框红描边 + 下方 12px 红字，`aria-describedby` 指向错误文本。
- 表单栅格：桌面 2 列（`grid-template-columns: repeat(2,minmax(0,1fr))`），`full` 字段跨 2 列，移动 1 列。
- **一屏一屏填**：超过 8 个字段的表单分「基本信息 / 库存信息 / 备注」三组，组间 24px 间隔 + 组标题（`--fs-h3`），不用分步向导（实验室场景要能一眼看全）。

### 4.3 数据表格（本次重设计的核心）

| 规格 | 值 |
| --- | --- |
| 表头 | 底色 `--c-subtle`，13px/600，`--c-text-2`，粘性定位 `position:sticky; top:0` |
| 行高 | 单行 44px；双行（主+副）64px |
| 单元格内边距 | `12px 16px`（现 `14px 18px` 偏松，压缩后一屏多显示 2–3 行） |
| 行分隔 | `1px solid var(--c-line-soft)`，不用斑马纹 |
| 悬停 | 整行 `background: var(--c-primary-50)` |
| 选中 | 左侧 3px 蓝条 + `--c-primary-50` 底，行首 checkbox |
| 数字列 | `text-align:right; font-variant-numeric: tabular-nums`；单位紧跟数字，12px `--c-text-3` |
| 首列 | 14px/600 主文字，第二行为 12px `--c-text-3` 副文字（**最多两行**） |
| 操作列 | 右对齐，幽灵按钮，超过 3 个收进「⋯」 |
| 横向滚动 | `min-width: 720px`，容器 `overflow-x:auto` + `overscroll-behavior-x:contain`（保留现有做法） |
| 空表 | 不显示空表头，改为空状态块 |

**验收表格的具体重构**（现在 6 列塞 4 个数据点）：

| 现列 | 问题 | 新列 |
| --- | --- | --- |
| 物资 / 分类 / 区域（4 个数据点） | 过载 | **物资**（名称 + 编码）、**区域 / 仓库**（独立列） |
| 规格 / 来源单据 | 两类信息混排 | **规格**、**来源单据**（单号 + 版本，mono 字体） |
| 申报 / 已验 / 结案 | 三个数字一行 | **申报数量**、**待验收**（重点，加粗）、**进度**（细进度条 + "6/10"） |
| 剩余数量 | 与上一列重复 | 合并进「待验收」 |
| 状态 | 纯文字 | 状态徽章（三重编码） |
| 操作 | 4 个按钮平铺 | 「办理验收」+「⋯」 |

列数从 6 增至 7，但**每列只承载一个语义**，扫读路径变成垂直的单列扫描。

### 4.4 状态徽章

统一 `inline-flex`，高 22px，`padding: 0 8px`，`--r-sm`，12px/500，前置 6px 圆点：

| 状态 | 语义色 | 圆点 |
| --- | --- | --- |
| 草稿 / 已取消 | neutral | 空心圆 |
| 已提交 / 待处理 | info | 实心圆 |
| 未验收 / 待发放 | warning | 实心圆 |
| 部分验收 | warning | 半圆（`conic-gradient`） |
| 已验收 / 已发放 / 充足 | success | 实心圆 |
| 差缺结案 | neutral | 实心圆 |
| 已驳回 / 已过期 / 异常 | danger | 实心圆 |

**三重编码的意义**：色彩单独使用对红绿色盲不友好；圆点形状提供第二通道；文字是无障碍的兜底。

### 4.5 面板、卡片与空状态

- 面板：`--c-surface` + `1px solid var(--c-line)` + `--r-lg` + `--shadow-panel`，标题区 20px padding。
- 工具栏与表头之间用 1px 分隔，不嵌套卡片（现 `mw-toolbar` 有独立底色 `#fbfcfe`，视觉上形成第二层卡片）。
- 空状态：居中式，SVG 线性插图（64px）+ `--fs-h3` 标题 + 13px 说明 + 一个主按钮（如"新建申报"）。**不要只显示"暂无数据"**。

### 4.6 批量操作条

列表勾选 ≥1 行后，底部浮出操作条（`position:sticky; bottom:16px`，`--shadow-pop`、`--r-lg`）：

```
[已选 3 项]  [批量验收]  [批量结案]  [取消选择]
```

用于验收列表与领用列表。**这是"少点击"的关键**：现在只能逐行点"办理验收"。

### 4.7 对话框

- 桌面最大宽 720px（大表单 880px），`--r-xl`，`--shadow-pop`。
- 头/脚粘性（`position:sticky`，现移动端已做，桌面也统一）。
- 关闭按钮 32×32 图标按钮，右上角，`aria-label="关闭"`。
- 底部按钮右对齐：主按钮在右（现有约定保持），移动端满宽。

## 5. 关键界面设计

### 5.1 工作台

```
┌─ 今天要处理 ────────────────────────────────┐
│ [待我验收 6 项] [待审批领用 2 单] [待完善 3 项] [临期 4 批] │  ← 4 张卡，数字大号 28px
└──────────────────────────────────────────┘
┌─ 实验室概览 ────────────────────────────────┐
│ 总记录 1,284 ｜ 本月收入 ¥86,400 ｜ 支出 ¥52,100 ｜ 预警 3 │  ← 紧凑指标条
└──────────────────────────────────────────┘
┌─ 最近动态 ──────────┐ ┌─ 库存预警 ─────────┐
│ 时间轴（谁/做了什么） │ │ 低于阈值物资列表    │
└────────────────────┘ └──────────────────┘
```

### 5.2 物资申报

**列表**：单号 / 标题 / 提交人 / 提交时间 / 明细数 / 验收进度 / 状态 / 操作。
补上现有缺失的"提交人、提交时间、验收进度"三列（数据已有，`schema.js:87-94`）。

**详情**：头部是单据信息条（单号 mono + 状态徽章 + 创建人/时间 + 修订号），下面是明细表 + 右侧操作。不可匹配物资信息的行显示 warning 徽章「待完善」，**不阻断提交**。

**新建/编辑明细**：名称字段旁给"检索已有物资（可选）"的搜索按钮，不强制；未选中时下方中性提示「验收时再完善物资信息」。

### 5.3 验收入库（最重要的改造）

三区布局：

## 7. 响应式与移动端（功能对等，不砍功能）

**前提**：手机端与桌面端**功能完全对等**。差别只在"呈现形态"和"操作步数"，不在"能不能做"。手机上没有"请用电脑"这类提示页，也没有只读页面。

### 7.1 断点

| 断点 | 设备 | 侧栏 | 表格形态 | 表单列数 |
| --- | --- | --- | --- | --- |
| ≥ 1280px | 桌面宽屏 | 220px 完整 | 8 列全显 | 2 列 |
| 1024–1279px | 笔记本 / 横屏平板 | 220px 完整 | 8 列，次要列可折叠 | 2 列 |
| 768–1023px | 平板竖屏 | 64px 图标条 | 保留表格 + 横向滚动 | 2 列 |
| 390–767px | 手机竖屏 | 抽屉 + 底部 tab | **表格转卡片** | 1 列 |
| ≤ 389px | 小屏手机 | 同上 | 卡片，间距压到 12px | 1 列 |

断点值用 `1280 / 1024 / 768 / 390`，替换现有 `1100 / 900 / 600`（旧值在 `material.css` 里散落，改造时同步收敛到 `tokens.css` 尾部统一管理）。

### 7.2 导航三态（同一份 DOM）

不维护两套菜单，`<nav>` 内容只有一份，三种形态靠容器类和定位切换：

| 形态 | 触发 | 结构 |
| --- | --- | --- |
| 侧栏 | ≥ 768px | 现有 `.sidebar` |
| 图标条 | 768–1023px | 同 `.sidebar`，`width:64px`，隐藏文字，`title` 提供悬浮提示 |
| 抽屉 | ≤ 767px | 同 `.sidebar`，`position:fixed; transform:translateX(-100%)`，`body.drawer-open` 滑入；遮罩点击/Esc 关闭 |

手机底部固定 tab bar，5 项：**工作台 / 物资 / 验收 / 库存 / 更多**。

- 前 4 项是高频直达，第 5 项打开抽屉（列出全部 13 个模块，含管理页）。
- 选这 4 项而不是"记录/待办"：工作台首屏本身就是待办，验收和库存才是每天要进两次的地方。
- 领用与扫码归到「物资」tab 下（二级页时父级 tab 保持高亮）。
- 「更多」抽屉里再分"业务 / 系统"两组，与桌面侧栏分组一致。
- 当前页所属 tab 高亮；进入二级页（如申报单详情）时，父级 tab 保持高亮。
- 待办 tab 带未读数角标。

### 7.3 表格转卡片（本方案的关键工程决策）

**单套 DOM，CSS 重排。** 禁止为手机另写一套卡片模板——那意味着 `material.js` 里要维护两份 `innerHTML`，是本项目最容易出错的地方。

```css
@media (max-width:767px){
  table.data{min-width:0;display:block}
  table.data thead{display:none}
  table.data tr{display:grid;grid-template-columns:1fr 1fr;gap:2px 12px;
    padding:14px 16px;border-bottom:1px solid var(--c-line)}
  table.data td{display:block;padding:0;border:0}
  table.data td::before{content:attr(data-label);display:block;
    font-size:12px;color:var(--c-text-3);margin-bottom:1px}
}
```

配套约定：

| 类 / 属性 | 作用 |
| --- | --- |
| `td.cell-key` | 卡片标题行，跨 2 列，14px/600；前不放 `data-label` |
| `td.cell-act` | 操作区，跨 2 列，右对齐，顶部 1px 分隔 |
| `td[data-optional]` | 低频字段，手机默认收进「展开」；点卡片标题展开（纯 CSS `:has` 或一行 JS 切类） |
| `data-label` | 每个 `td` 必填，与 `th` 文案完全一致 |

约束：

- 一张卡最多显示 6 个字段，超出走 `data-optional`。
- 数字列在卡片里**不右对齐**（破坏扫读），改为「标签 + 值」的常规排布。
- 分组表头（`rowspan` 的物资名）在手机上转为组标题卡，不计入字段数。
- 表格的横向滚动**只在平板档保留**，手机档必须彻底放弃横滚。

**怎么落地（给执行的 AI）**：旧代码有几十张表，逐张手写 `data-label` 不现实。推荐一次性注入，页面里跑一次即可：

```js
document.querySelectorAll('table.data').forEach(t => {
  const head = t.tHead?.rows[t.tHead.rows.length - 1];
  if (!head) return;
  const labels = [...head.cells].map(c => c.textContent.replace(/\s+/g, ' ').trim());
  [...t.tBodies[0].rows].forEach(tr => {
    const cells = [...tr.cells];
    if (cells.some(c => c.colSpan > 1)) return;        // 分组行跳过，靠 CSS 收成组标题卡
    cells.forEach((td, i) => {
      if (td.querySelector('.row-actions')) { td.classList.add('cell-act'); return; }
      if (!td.dataset.label && labels[i]) td.dataset.label = labels[i];
    });
    const key = cells[0]?.classList.contains('cell-chk') ? 1 : 0;
    cells[key]?.classList.add('cell-key');              // 主字段作卡片标题
  });
});
```

两个必须处理的坑：

- **`colspan` 分组行**必须跳过注入，否则标签整体错位（原型里 `group-head` 就是这种行）。
- **首列是勾选框**时，`th` 文本为空、`label` 会算出空串，要把 `cell-key` 移到第 2 列，并把勾选框浮到卡片右上角（`.cell-chk`）。

### 7.4 双栏 → 分区推进（验收、详情这类页面）

桌面左右分栏（左选右填）在手机上**不允许简单上下堆叠**——6 行明细 + 12 个字段的表单会超过 3 屏，用户滚回去改上一项要滑很久。

统一做法：

```
第 1 步：选明细（列表 + 底部固定条「已选 3 项 · 办理验收」）
第 2 步：填表单（sheet 从底部升起，高 92dvh − tab bar，tab bar 保持可见可点）
第 3 步：提交 → 关闭 sheet → 回列表并高亮刚处理的项
```

- sheet 头部固定（拖拽条 + 标题 + 关闭 ×），主体可滚，底部固定「取消 / 主操作」。
- sheet **不盖住底部 tab bar**：用户中途可以直接切到库存查一下再回来，不必先关表单。
- sheet 内表单 1 列，输入框 44px 高。
- 多选批量时，sheet 标题显示「批量验收 3 项」，字段说明"将套用到全部选中项"。
- 手机上**只留一条底部浮层**：桌面那条批量操作条（`.bulkbar`）在手机档隐藏，批量入口并进推进条与 sheet。

**判据**：任何"左列表 + 右表单"的界面，手机档都必须走这套，不允许直接堆叠。

### 7.5 触控与移动输入

| 项 | 值 | 原因 |
| --- | --- | --- |
| 最小点击区 | 44×44px | 戴手套 / 走动中操作 |
| 行内幽灵按钮 | 视觉 28px，`::after` 扩到 44px 命中区 | 不撑大表格行 |
| 输入框高度 | 44px | — |
| 输入字号 | **16px**（不小于） | 低于 16px 时 iOS Safari 会自动放大页面 |
| 数字输入 | `inputmode="decimal"` / `numeric` / `tel` | 唤起数字键盘 |
| 底部固定元素 | `padding-bottom: calc(12px + env(safe-area-inset-bottom))` | 避开 iPhone 手势条 |
| 视口高度 | `100dvh`（不用 `100vh`） | 地址栏收起时 `100vh` 会裁切 |
| 横向滚动容器 | `-webkit-overflow-scrolling:touch` + `overscroll-behavior-x:contain` | 避免带动整页 |
| 分段控件溢出 | 横滑 + 右侧 24px 渐隐遮罩 | 提示"还有更多" |
| 手势 | **不作为唯一入口**（不用左右滑删除、不用长按菜单） | 实验室场景，误触代价高 |

### 7.6 手机端必须可用的功能清单（验收用）

| 模块 | 手机端要求 |
| --- | --- |
| 工作台 | 待办卡单列全宽，点击直达 |
| 物资申报 | 新建 / 编辑 / 提交 / 删除明细，全部可用；明细表转卡片 |
| 申报单详情 | 头部信息折叠为两行；明细卡片；动作收进底部固定条 |
| 验收入库 | 两步流（7.4）；未匹配物资就地检索/新建；批量套用 |
| 库存台账 | 7 列转卡片；批次展开；搜索与筛选常驻；导出走系统分享 |
| 领用 | 申请 / 审批 / 发放 / 退回全部可用；审批动作在卡片底部 |
| 扫码 | 全屏相机 + 结果卡 + 入库/领用 |
| 管理页（实验室/项目/方法/用户） | 列表转卡片，增删改查完整 |

**唯一例外**：批量导入 Excel 与打印排版在手机上只读提示（浏览器无法可靠读写本地文件、打印），这是能力限制而非设计取舍，需在界面上说明原因。

## 8. 页面骨架模板（供后续新页面直接复用）

前 7 节定义"零件"，本节定义"骨架"。**新增任何页面都必须先归到下面 4 种之一**，不允许自创布局——否则一年后又会长出 13 种互不一致的页面。

### 8.1 四种骨架

| 骨架 | 用于 | 桌面结构 | 手机结构 |
| --- | --- | --- | --- |
| **L 列表页** | 申报列表、库存、领用、审计、用户 | 标题 + 筛选条 + 表格 + 批量条 | 标题 + 搜索常驻 + 筛选收进「筛选」按钮 + 卡片流 + 批量条贴底 |
| **D 详情页** | 申报单、领用单、记录详情 | 单据头 + 明细表 + 右侧动作栏 | 单据头两行 + 明细卡片 + 动作收进底部固定条 |
| **F 表单页** | 新建申报、物资档案、用户编辑 | 分组表单 2 列 + 右下提交 | 分组表单 1 列 + 底部固定提交 |
| **B 看板页** | 工作台、统计 | 指标条 + 卡组 2 列 | 指标条 2×2 + 卡组单列 |

### 8.2 L 列表页（最常用）

```
┌ 标题区：h1 + 说明 + 主按钮（1 个）────────────────────┐
├ 筛选条：搜索框（主）+ 2–3 个下拉 + 「筛选」高级项 ────┤
├ 表格 / 卡片流 ──────────────────────────────────┤
└ 批量操作条（勾选后浮出）──────────────────────────┘
```

- 搜索框**永远在第一位**，宽度 240–280px。
- 筛选条件超过 3 个时，只留最重要的 2 个外露，其余进「筛选」按钮（带生效数量角标）。
- 手机：搜索框满宽常驻顶部（滚动时不消失），筛选按钮在右。
- 表格必须带 `data-label`，否则手机端卡片没有字段名。
- 空状态区分两种：**无数据**（引导新建）与**筛选无结果**（引导清除条件），文案不同。

### 8.3 D 详情页

- 头部信息条：单号（mono）+ 状态徽章 + 创建人/时间 + 修订号，一行装完；手机折成两行。
- 明细区：桌面表格，手机卡片（7.3）。
- 动作区：桌面右上 + 行内；手机**全部**收进底部固定条，最多 2 个主按钮 + 「⋯」。
- 关联信息（审计轨迹、附件）放明细下方折叠区，不单独开页。

### 8.4 F 表单页

- 分组：每组一个 `h3` + 24px 组间距；字段超过 8 个必须分组。
- 桌面 2 列，`full` 字段跨列；手机 1 列，**字段顺序即填写顺序**（不做桌面/手机两套顺序）。
- 校验：失焦校验 + 提交时汇总；错误提示在字段下方，不弹 toast。
- 手机：底部固定提交条，主按钮满宽 44px；表单未改时按钮置灰。
- 危险操作（删除、作废）不放底部条，收进「⋯」，需二次确认。

### 8.5 B 看板页

- 指标条最多 5 个数字，超出分两行或改成卡组。
- 手机：指标 2×2 网格（不横滑），卡组单列。
- 卡片必须有明确点击目标（整卡可点），且点击后**落在具体列表**而不是首页。

### 8.6 新页面接入清单

新增页面前逐条确认，7 条全过才算合规：

- [ ] 已归入 L / D / F / B 之一，没有自创布局
- [ ] 使用 `tokens.css` 变量，无硬编码色值
- [ ] 表格每个 `td` 带 `data-label`，主字段标 `cell-key`，操作列标 `cell-act`
- [ ] 在 390px 宽度下无横向滚动（表格自身滚动除外）
- [ ] 所有可点元素命中区 ≥ 44×44px（手机档）
- [ ] 空状态有插图 + 说明 + 主行动
- [ ] 有 `aria-label` / `th[scope]` / `label[for]`，键盘可全程操作

## 9. 落地路径

与 `docs/优化方案.md` 的批次对齐，**UI 改造不单独开版本，跟着功能批次走**：

| 阶段 | 范围 | 风险 |
| --- | --- | --- |
| 第 1 步（随批次 A/B） | `tokens.css` + **响应式骨架**：断点收敛、抽屉导航、底部 tab、`table.data` 卡片化规则、12 个 SVG 图标、侧栏分组 | 中，纯样式但覆盖面广；**必须与第 1 个功能页同批，否则后续每页都要返工** |
| 第 2 步（随批次 B） | 验收页双端：桌面三区 / 手机两步流 + 就地匹配或新建物资；状态徽章全面替换 | 中，涉及 `material.js` 页面结构 |
| 第 3 步（随批次 C） | 库存台账 7 列 + 分组表头 + 展开行 + 手机卡片 | 中 |
| 第 4 步（随批次 D） | 领用退库界面 + 批量操作条（双端） | 中 |
| 第 5 步（随批次 E） | 工作台待办优先 + 信息架构重排 + 扫码页双端 | 中高，动 `app.js` |
| 第 6 步（收尾） | 13 个旧模块逐个套 8.1 的骨架模板，补齐 `data-label` | 低，纯增量 |

**移动端不是最后一步**：第 1 步就把骨架和表格契约立起来，后面每个页面天然双端可用；反过来先做桌面再补手机，等于每页做两遍。

**不做**：不引入 CSS 框架、不引入 Web Font、不做前端构建链、不改现有类名体系（新样式用新类名叠加，旧类名保留，避免一次性大改导致回归面失控）。

**原型**：`docs/prototypes/ui-redesign.html`（桌面，直接打开）、`docs/prototypes/ui-mobile.html`（手机，390×844 真机尺寸并排预览）。
