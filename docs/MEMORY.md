## 技术结构与目录

- 后端使用 `node:http`、`node:sqlite` 的 `DatabaseSync`、`node:fs` 和 `node:crypto`，没有第三方 npm 依赖。
- 前端为原生 HTML/CSS/JavaScript 单页应用。历史脚本通过动态加载和全局导航包装扩展页面，本轮统一公共导航与记录状态，业务脚本保留渲染职责。
- 8 个业务模块：档案、电子模板、财务、设备、物资、体系文件、人员和合同。
- 共用 `records` 表，扩展业务字段存 JSON；另有用户、会话、附件索引、审计、角色权限、导航和工作台配置表。金额和数量使用 `REAL`，业务约束仍较弱。
- 附件存本地文件，元数据存 SQLite。`deploy/docker-compose.yml` 仅配置 PostgreSQL 和 MinIO，应用没有接入这些服务；`DATABASE_URL` 尚未使用。

## 运行与数据隔离

| 命令 | 默认行为 |
| --- | --- |
| `npm start` | 端口 3000，运行根目录 `var/` |
| `npm run dev` | Node watch 模式加 `--dev`，端口 3001，运行根目录 `var/development/<package.version>/` |
| `npm run check` | 解析 `src/`、`scripts/`、`tests/` 中全部 JavaScript，不启动业务服务 |
| `npm test` | `tests/*.test.js` 回归，副本统一位于 `artifacts/cache/<version>/`，不使用真实运行数据 |
| `npm run package:zip` | 按版本输出 `artifacts/releases/<version>/labos-<version>.zip` 和 `manifest.json` |

- 每个运行根目录下分别有 `data/`、`uploads/`、`logs/`；创建日志目录不代表已实现自动文件日志。
- `PORT` 可覆盖端口，`LABOS_RUNTIME_DIR` 可覆盖运行根目录；相对路径按项目根解释。显式将不同环境指向同一路径仍会共用数据。
- Git 分支或标签只隔离代码，不隔离或回退数据库。即使在 `develop`，执行 `npm start` 仍使用普通运行目录；开发应执行 `npm run dev`。
- `config/.env.example` 只供参考，配置须传入进程环境；初始化管理员环境变量不会修改已有用户密码。
- 部署 ZIP 保留项目目录结构，可执行 `npm start` 或 `start-labos.cmd`；包中不含本地运行数据、日志、真实 `.env` 或 Git 元数据。
- 0.1.1 的开发路径原为 `var/development/`；从本候选版起追加版本号，不自动搬入旧版开发数据。普通 `npm start` 的 `var/` 路径保持原约定。
- 清单记录版本、构建提交、源码文件摘要、ZIP 大小与 SHA-256 和 UTC 构建时间。同版本同内容且校验通过才复用，内容变化或缓存损坏拒绝覆盖；下一版使用新版本号并保留旧包。

## 历史发现及本轮处理状态

以下原始发现来自初次源码分析及有限自检；0.1.1 没有修复这些业务问题。保留发现并在各项补充 `0.2.0-rc.1` 的处理状态；回归范围见下节，不等于全面安全或业务验收。

### 页面与维护

1. 档案、设备、体系、合同的导航包装器绕过公共 `current/items` 更新；各页面使用独立 `__*Rows`，公共查看/编辑仍读公共状态。Node VM 按完整加载顺序复现查看取不到记录；设备、体系、合同的新建可能误入资料档案。相关文件为 `app.js`、`archive.js`、`asset.js`、`quality.js`、`contract.js`。
2. 设备阶段筛选与计数将英文阶段键与中文存储值直接比较，导致分类结果错误，位于 `asset.js`。

上述两项在本轮统一 `go/load/current/items` 和设备阶段映射后修复；保存、删除和搜索沿公共加载流程刷新，过期请求不会覆盖新页面。权限入口按登录响应中的有效权限隐藏；冲突时保留表单，显式重载后再编辑。修复触及表单与物资显示的 HTML 转义，不代表完成全站 XSS 审计。

3. 设备附件统计逐台串行请求，记录增多会拖慢页面。
4. 大量长行代码、重复函数声明和全局覆盖增加维护难度。

后两项仍有遗留；本轮只移除影响公共导航的包装，未全面重构页面或实现附件批量统计。

### 权限、会话与数据保护

1. `src/server.js` 启动时仍无条件永久删除旧 `samples` 记录及附件索引，遗留附件实体；这是既有破坏性初始化逻辑。
2. 密码以明文保存与查询；完整备份包含用户密码。
3. 登录 Cookie 使用 `Path=/`，退出清除时遗漏同一路径，也未撤销数据库会话。
4. 记录列表有分区权限过滤，但新增、修改、删除主要只检查模块权限，没有统一执行分区和档案数据范围授权。
5. 附件上传仅要求登录，缺少记录存在和写权限校验；列表、下载缺少完整模块/分区读取校验，也未完整处理回收站权限。
6. 导出或备份不指定模块时，缺少逐记录的模块与分区读取校验。工作台统计也未按用户权限过滤全部汇总数据。
7. 恢复接口仅要求恢复权限，却可导入管理员账号、覆盖角色权限，越过单独的权限管理授权边界。
8. 现有备份恢复更接近追加导入：遗漏部分系统配置和回收站；审计历史与原始时间不能完整恢复，重复恢复会产生重复记录，文件写入不随 SQL 回滚清理。

本轮对第 1–7 项实施修复：保留旧 `samples` 记录、附件索引及旧权限，只隐藏旧入口；密码改用带盐 scrypt，旧明文账号成功登录后升级，备份中的旧明文转换为哈希快照；退出撤销 token 并按 `Path=/` 清 Cookie，改密撤销该用户会话；记录、附件、导出、备份、工作台、回收站、模板导入统一执行模块、分区及档案角色范围授权。完整备份的账号/角色要求额外的 `permissions.read`，审计要求 `audit.read`；恢复非空账号/角色内容额外要求 `permissions.write`，并验证导入内容。

第 8 项仅补充恢复失败时清理新写附件，完整灾备语义仍未完成，恢复接口仍跳过不支持的旧 `samples` 等模块。备份含密码哈希，仍属于敏感文件；旧账号未成功登录前本地旧明文仍可能存在，旧历史备份也不会被自动改写。尚未增加账号停用、自助改密、登录限速或多因素认证。

分区兼容性：物资中文流程和财务收支方向本轮映射到权限代码，模板/人员表单增加英文权限键与中文标签的分类选择，财务方向增加预算。某动作只授予部分分区时拒绝缺失/未知分类；全部已知分区授权视为全模块范围，默认经理可维护未分类历史记录。物资采购申请、到货验收及仓储环境暂未有对应权限目录，部分分区受限角色不能操作这些环节。前端仅按模块/动作提供便利提示，分区和角色范围由后端强制，权限调整后重新登录刷新页面入口。

### 并发与规模

- 同步 SQLite、同步附件操作和全量备份会占用 Node 主线程。
- 原记录 PUT 按完整字段覆盖，可能多人修改相互覆盖。本轮新增整数 `records.version` 和条件更新；PUT 缺失版本返回 400，旧版本返回 409，软删除、恢复和体系文件当前版本联动也递增版本。旧客户端必须先读取并回传 version。
- 出入库等联动操作需要事务与原子更新；列表分页、必要索引和附件批量统计仍待改造。
- 没有外键等完整约束，尚无真实业务一致性和负载验收结果。
