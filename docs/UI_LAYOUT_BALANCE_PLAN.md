## 0. 优化方案V1（本次评审稿）

用户在布局评审和网络参考后要求给出一版优化方案。本节将前文调研收敛为**一套推荐方向**，不是新增多套皮肤让用户比较；第1至9节保留问题、依据、参考及验证历史。本节是待确认设计，不替代现行施工卡。所有尺寸为本项目的拟议值，不声称来自外部规范或已在正式系统实现。

### 0.1 目标与范围

**目标：列表充分用宽、编辑区优先、短表单限宽、手机突出主次。** 解决空间错配，不把“铺满屏幕”当完成标准。

- 本批覆盖物资申报、验收、库存、物资信息库、资料档案、编号设置，以及它们使用的新建／编辑／详情工作区。
- 保留现有品牌、245px展开侧栏与72px紧凑侧栏、唯一全局账号／版本／退出。正式系统其他模块及权限入口不因原型省略而删除。
- 保留原生前端、接口、业务字段与数据含义，不引入UI组件库、密度切换器、统计大卡片或新的全局设置模块。
- 不改业务流程、库存事务、权限、批量幂等、备份格式和打印模板；新位置上的操作仍走原校验与状态保护。

### 0.2 统一排版与空间分配

| 项目 | V1拟议规则 | 要避免的做法 |
| --- | --- | --- |
| 字号层级 | 页标题22px，区块标题18px，正文／表格14px，标签／表头13px，辅助说明12px；已有micro特例保持原范围 | 全站缩字号，或每个字段都加粗／着色以争夺注意力 |
| 页面边距 | 桌面20px、手机12px；同组控件间8px，组内内容12至16px，独立内容组之间24px | 每一行都拉大间距，或相关标签与值相隔过远 |
| 列表宽度 | 占满可用工作区；短字段按语义约束，名称／规格接收余宽 | 所有页面套统一最大宽度，或所有表格列等分 |
| 内容限宽 | 短表单居中且最大760px；详情最大1120px；设置最大1040px | 让五条设置横跨1920屏幕，或用无关内容填满左右空白 |
| 行与控件 | 桌面控件36px；单行记录目标44至56px，多行内容自然增高；手机触控目标至少44px | 固定行高裁切长值，用小图标代替可点击面积 |
| 顶部层级 | 全局头、必要业务页签、标题动作、一行基本筛选；低频操作收进更多，高级条件按需展开 | 重复账号、重复主操作、常驻多排筛选与说明 |
| 操作层级 | 每个任务区一个主要提交动作；返回／取消为次级；工具图标有名称和悬停提示 | 将导出、删除、配置与日常主操作全部做成同等级大按钮 |

上述间距是常态目标，不得通过固定高度隐藏错误、强制截断长名或阻止低高度滚动来达标。较短列表自然结束后留白，不强撑表体。

表中列宽只作用于明确语义类，不能用“第几列”去猜日期或金额，也不把其他模块全部改成fixed表格。正式施工先核对完整字段和极端值，再在本范围内校准，不通过删除业务字段获得紧凑效果。

### 0.4 典型结构与窄屏规则

```text
列表：标题＋主操作 → 搜索＋高级筛选入口 → 结果表 → 分页
验收：单据摘要＋切单 → 办理／历史／资料 → 验收行 → 选择摘要＋提交
表单：标题＋返回 → 分组字段 → 校验信息 → 取消／保存
设置：页面标题 → 局部导航＋限宽内容
```

- 1280px及以上，普通列表尽量直接比较各列，名称和规格使用剩余宽度，不为所有字段固定同宽。
- 768至1279px，普通列表可在表格内部必要滚动，整页不横向溢出，行操作与菜单不被裁切。
- 验收在1100px及以下使用同一DOM转为多行编辑网格；数量、金额、厂家和位置仍有可见标签，不因“简洁”藏到逐项弹窗。
- 360至767px，库存等普通记录的短字段使用两列；359px及以下再单列；名称、备注和操作占整行。DOM字段关联与读屏顺序需与视觉顺序一并核对。
- 低高度允许内容滚动，保存、取消、错误及末字段必须可达。规则仅用于屏幕，不覆盖原单、A4报表或标签打印。

### 0.6 验收标准

1. **宽度分配**：1366×768的标准验收样本中，常驻编辑字段不需横向滚动即可操作；普通列表中操作列不被迫逐按钮竖排，长名称可完整查看。
2. **首屏效率**：390×844、默认收起高级筛选、无错误提示的标准库存样本，第一条记录目标在视口顶部320px以内开始。现有参考约260px仅为该样本观测，不是所有生产页的保证。
3. **合理留白**：1920×1080时设置正文不超过1040px，短表单不超过760px；少量记录不加占位空行，不用统计卡片补空。
4. **可达性**：360×800、390×844和1366×480时无整页横向溢出；低高度下末字段、错误、返回和保存可滚到。长值、金额、单位、菜单及触控区域不互相遮挡。
5. **状态与功能**：权限、筛选／页码返回、表单未保存保护、忙态、未知结果、实际全局退出、单据切换及三级返回保持原合同。权限动作不得仅因换成图标而失去可访问名称。
6. **验证分层**：普通／严格UI审计和语法检查只是门槛；正式实施还需前端VM、专用临时PG＋真实API浏览器及现有全量测试。截图覆盖第7节视口与长值／空态／错误态，原生缩放及实体设备未测则另列，不能拿等效视口冒充。

## 1. 结论

问题不是单纯的“间距大”或“字号小”，而是**页面没有按任务分配空间**：编辑表和选单栏同时争宽度，短字段按百分比放大，多个导航／标题／工具栏反复占高度，手机把桌面所有字段都等权堆叠。

建议沿用现有品牌、14px正文、13px标签、36px桌面控件和44px触控下限，只调整结构及内容密度。不继续全站缩字号、不追求所有内容一屏、不用装饰卡片填满空白。

下方空白不一定是缺陷。只有两条记录的列表可以自然结束；短表单在宽屏保留侧边空白也合理。应消除的是**一处有空位却不给需要的字段，另一处被挤到换行或横向滚动**。

## 5. 密度规则

### 横向

- 记录列表使用可用工作区，不给所有页面套统一最大宽度。短字段用语义列宽，长名称及规格分配剩余空间。
- 短表单760px、详情1120px、设置1040px为本方案参考值。宽屏不强行拉伸这些内容，也不放无关卡片占空白。
- 普通列表在768至1279宽度允许表内必要滚动，不允许整页横向溢出；操作不能因表内滚动变不可达。
- 验收在1100px及以下用同一DOM转成多行编辑网格，避免把八列硬塞进去；厂家、位置和金额仍可直接办理。

### 纵向

- 表格保留14px正文、13px表头和8×12px单元格间距；不使用缩字解决宽度问题。单行目标约44至56px，双行内容自然增高，不裁切完整名称。
- 顶部通常只有全局头、业务页签、标题动作和一行筛选。展开筛选保留明确起始／结束日期标签，筛选生效后显示当前条件和清除入口。
- 不根据全表最高的一个长文本行决定所有行的分页容量。建议固定每页条数，并提供10／20／50选项；少量数据不强撑表高。是否落到各现有服务端分页合同，实施时分别核对。
- 低高度允许工作区滚动。不得固定一个计算高度再隐藏溢出，也不得压缩或隐藏错误、末字段和保存／返回操作。

### 手机

- 保留同DOM；库存主字段用语义类定位，而不是全局第一列规则。
- 360至767px可容纳的短字段采用两列，359px及以下再单列；长名称、备注和操作仍占整行。
- 全局账号、版本和退出仍由唯一头部提供。参考中手机将账号及版本上下排列，退出使用有可访问名称的图标。
- 参考390×844库存首条记录实测约260px开始；原约650px来自既有截图，两者数据及工具布局不同，不能把该差值当成所有真实页面的保证。
