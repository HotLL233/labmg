# 系统打印与二维码标签

当前说明面向**0.9.1验证版（已公开，2026-10-21）**，使用同版本Release配套附件。0.9.1补充纸张、模板状态和PDF排查提示，保留0.9.0撤除BarTender后的系统打印方式，标签只输出二维码和基础信息。打印通过连接USB打印机的电脑浏览器打开系统打印窗口；原0.8.2及更早的说明与验证记录在本页后部保留，不能作为新版入口。

## 打印步骤与纸张方向

1. 在库存批次或验收记录打开单件列表，选择“系统打印本页二维码标签”或打印本组标签；每件仍使用已生成的永久编号。批次二维码入口仍定位批次，不能替代逐件领用身份。
2. 在标签模板或打印页选择60×40mm、38.5×30.5mm或自定义尺寸。**纸张宽是横跨纸卷的宽度，纸张高是走纸方向的长度**；用户已确认当前纸为宽38.5mm、走纸长30.5mm。内容方向单独选择“不旋转（0°）”或“旋转90°”，切换内容方向不交换实体纸张宽高，也不改变最终页面尺寸。
3. 调整二维码和名称、规格、单位、单件编号、位置、批号、有效期等基础字段。旧模板中的Code128元素不再输出；模板不保存业务数据，也不重新生成编号。确认文字没有溢出、二维码没有被遮挡。
4. 在连接DL-886A（NEW）的Windows电脑安装并选用能正常出纸的驱动，建立宽38.5mm、高30.5mm的用户纸张，核对介质间隙和送料设置；60×40mm纸另建规格。点击“试打所选首张”，系统窗口选择该打印机和对应实体纸规格，使用驱动正常走纸的方向、100%缩放、每张一份、边距设为无，关闭页眉页脚及“适合页面”等自动缩放选项。内容已在网页内旋转，不要在驱动中再旋转一次；先试打一张并回扫，再打印所选范围。

网页内容旋转只改变纸内内容，CSS最终页面始终使用实体宽×走纸长；水平／垂直校准按实体纸左上角计算。旧模板缺少旋转值时按0°读取，保留原宽高及坐标，不猜测旧版横纵向含义；原模板尺寸错误时，重新选实际规格并检查预览。浏览器的系统打印接口不接受打印机名或驱动纸张参数，仍由系统窗口确认设备和驱动设置。不能仅凭预览或导出PDF认定物理送料已通过。官方接口说明：[Window.print()](https://developer.mozilla.org/en-US/docs/Web/API/Window/print)、[CSS @page size](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@page/size)。

## 0.9.1：先核对模板与纸卷

打印页顶部醒目显示“本次纸张：纸宽×走纸长”和内容0°／90°，下方对预设及自定义尺寸都提示核对实际纸卷和驱动。当前纸宽38.5mm、走纸长30.5mm时，应同时在网页和驱动使用这两个实体尺寸；名称不必相同，尺寸及送料含义须一致。网页不能读取驱动纸型、探测已装纸卷或自动选择USB打印机。

模板状态区会区分：读取到已保存模板；当前浏览器和访问地址下没有模板；已保存模板无效；浏览器不允许读取存储。后三种情况从60×40mm示例载入初始布局并说明原因，不覆盖原设置；先重新选择实际纸卷规格，后续以当前纸张设置为准。修改后显示“尚未保存”，需要点击“记住纸张与布局”供下次使用；保存失败时按页面错误处理，或导出模板JSON备份。

模板属于当前浏览器和当前网站地址来源，不随账号同步。换电脑、浏览器、HTTP／HTTPS、域名或端口以及清理站点存储后，需重新选纸或导入模板JSON；旧有效模板保持原有尺寸和布局。纸卷尺寸与模板是否匹配不能由预览自动判断。

## 0.9.1：通过PDF辅助排查方向与内容

1. 建议先把起止张设为同一张，核对顶部纸宽×走纸长和内容方向，再点击“保存 PDF（系统窗口）”。此入口与打印一样先重读未提交输入，遇到无效范围、元素越界或实际文字溢出时拒绝打开窗口。
2. 在浏览器打印窗口手动选择浏览器自带的“另存为 PDF”，使用100%缩放、无边距并关闭页眉页脚。按钮不会自动生成文件、指定保存位置或确认保存成功。Windows的“Microsoft Print to PDF”是另一条驱动输出路径，排查时记录实际选择的目标，不将二者混为同一测试。
3. 打开保存文件，核对页数、页尺寸、文字方向、二维码和基础字段是否完整。参考页尺寸按毫米×72÷25.4换算：60×40mm约为170.08×113.39pt，38.5×30.5mm约为109.13×86.46pt；浏览器生成的MediaBox可能有少量取整差异。切换内容0°／90°后实体页尺寸应保持相同。
4. 若PDF也异常，保留文件、实际使用的输出目标、网页尺寸和相关截图供进一步定位；不能直接推断为某种浏览器策略。若PDF正常，再核对实际打印机驱动纸型、缩放、方向、介质校准并试打一张。PDF结果只覆盖该输出路径，不能证明整个程序无缺陷或USB送料已通过。

偏移校准沿实体纸左右／上下方向，先小量调整并试打，不用整体缩放掩盖纸型错误。设备实际不可打印区、DPI、间隙和热敏效果需按驱动与实物核实，本项目未确认固定硬件边距。模板中较长文字或贴边元素仍可能需要重新布局，最终须回扫二维码并目视字段齐全。

本轮参考的用户排查报告未附当前仓库可找到的原始复现脚本和PDF，其中“已排除程序缺陷”及驱动裁切结论未作为已确认根因；不为此改变0.9.0的实体页／内容旋转数学。0.9.1本机完整184项183通过、0失败、1本机Docker条件跳过；此轮在最后三条回落文案优化前启动，优化后标签25/25与37JS重跑通过。最终文案真实隔离Edge286项、6份双页PDF及6图通过，无未捕获异常，早期283项保留为阶段证据。正式PG18.6回归177/177、四项容器门禁及本机12件完整交付核验已通过，Release419049884已公开；详情见[版本说明](CHANGELOG.md)。浏览器专项只使用合成记录、列明纸型和系统打印请求拦截，未打开原生窗口或操作USB打印机；下文0.9.0结果保持其原有验证范围。

## 实物仍偏：固定一套参数再试

2026-10-21用户反馈0.9.1实物仍有截断，确认纸卷宽38.5mm、走纸长30.5mm，照片来自三次不同设置的试打，不能据此认定逐张漂移或量出补偿毫米数。只读检查本机`Deli DL-886A(NEW)（副本 1）`的Windows默认配置，纸宽104.1mm、纸长101.6mm，与实体纸不一致；默认配置不是照片中历史任务的参数，也不能单独确认根因。网页纸型不会自动修改驱动默认纸型。

1. 在Windows的该打印机“打印首选项”核对或建立宽38.5mm、高30.5mm的标签规格，保留其他工作模板使用的纸型。关闭旧打印预览后重新打开，在本次打印窗口再次核对同一规格；不要仅改网页纸型。
2. 先导出模板JSON备份，固定网页为38.5×30.5mm、内容0°、水平和垂直偏移均0；打印窗口使用100%缩放、无边距、每页一张并关闭页眉页脚和自动适配。不要同时更改方向、纸型和偏移来比较结果。
3. 同一套设置先保存一张浏览器PDF，核对一页、尺寸和内容；再在一个打印任务中连续打三张，比较相同字段距纸边的位置。若有空白或逐张变化，无打印任务时可连续短按三次FEED观察停纸位置，勿长按或盲改传感器参数。
4. 只有每张均以相同距离整体偏移时，才测量后小量调整网页偏移；纸长、送料、比例、方向及单个文本框问题不能靠整层平移修正。保留同一设置下的PDF与三张实物，避免混合试打结果误导判断。

本轮有限合成Edge检查中，10件输出10页、单选第5件输出1页、4–6件输出3页，0°／90°单件均1页，没有空白页；忽略CSS纸型的对照会变成大页。这仍不覆盖Windows原生打印预览、任务纸型或真实送料。本轮未改驱动、调用打印机或更改业务源码，不新增业务版本；实际试打待用户反馈。

## 一瓶／一件一条记录

物资信息库（原称“主档”）选择“逐件管理”，验收或期初／补录单入库时按整件数量生成固定编码。信息库 Excel 导入本身不生成实物或标签，确认入库后才生成。打开对应单件列表，选择“打印标签”或“导出 BarTender 数据”。一次最多 1000 件，历史标签重印使用原编码，不新增库存、不消耗新流水号。

旧物资保持原有数量管理，不能按数量猜测历史上每瓶的身份。批次二维码只定位批次；批次打印不能代替逐件台账。整件领用仍需人员申请、物资管理员确认并选择在库实物。

## 网页标签模板

在物资页点击“标签模板”，可修改纸张宽高、水平／垂直校准偏移，以及每个元素的位置、尺寸、字号和显示状态。毫米从纸张左上角起算，字号单位为pt。当前0.8.2提供已确认的60×40mm、38.5×30.5mm两种纸预设、自定义宽高和横纵方向，选择规格或方向时按比例适配已有网页布局；校准偏移保留毫米值并参与越界检查。预览显示真实码图，文字溢出标红，打印前拒绝越界或文字裁切；这些设置仍须与Windows驱动一致，不是已完成硬件校准。

示例数据的 Code128 和二维码实际生成后供预览，后续修改布局复用同一图片；这只是网页标签预览，不是 BarTender `.btw` 或打印驱动的原生预览。无效尺寸或偏移会清除旧预览并指出错误，防止把上一次有效版式误认为当前设置。模板仍使用 schema 1；旧模板中不合规的校准偏移会保留供修正，不静默丢弃。示例文字被裁切时标红并提示字段，保存按几何边界校验；打印前再检查实际所选实物的文字，避免用示例名称长度限制真实数据。

“条码铺满行宽”保留编码、条码高度与纵向位置，只将条码框扩展至左右约各留 1 mm，并计入校准偏移。自定义布局需查看是否遮住同一行的其他元素。窄纸上的长 Code128 仍可能过密，必要时取消 Code128 的“显示”、保留二维码，再保存模板；扩大版面或先试打回扫，不能靠缩短已入库编码解决。

模板只保存于**当前浏览器和网站地址来源**，不保存业务数据；清理站点存储、从 HTTP 改为 HTTPS、换端口／域名、浏览器或电脑后需要重新导入。用“导出模板 JSON”保存配置，其他电脑用“导入模板 JSON”复用。不要将浏览器模板当作业务备份。

## 内置 DL-886A（NEW）打印面板

从单件列表点击“打印本页条码／二维码”或“打印本组全部标签”，打开内置打印面板；批次二维码入口也使用同一面板。待所有条码图片加载后，才能打开系统打印窗口。

1. 当前0.8.2面板可直接选择两种规格、横纵方向、自定义宽高和毫米偏移，预览随输入更新，无需关闭重开。可“记住纸张与布局”保存到本浏览器；未保存时仅本次生效。样式与每页尺寸使用同一设置，Windows打印窗口仍须选择一致的纸张与方向；没有预设未确认的硬件DPI或驱动命令。
2. 填写“起始张”和“结束张”，从 1 开始且包含两端；下方预览只显示这个范围。每件仍对应原有固定编码，选范围或重印不会新增库存、实物或流水号。
3. 点击“试打所选首张”，仅把选中范围的第一张交给系统打印窗口；窗口关闭后预览恢复原范围。扫码核对标签与实物编码，再根据偏移调位置。
4. 点击“打开系统打印窗口”，打印选中范围。选择已安装且能正常工作的 DL-886A（NEW）驱动，驱动与网页设置相同纸张宽高，缩放 100%、每张 1 份，关闭页眉、页脚和适应页面。不要再在驱动中增加份数或序列化。

预览与按钮支持手机查看；USB 打印应在连接打印机的 Windows 电脑浏览器操作。面板没有读取打印机清单或指定设备名称的网页接口，`window.print()` 打开浏览器／系统打印窗口，由用户选择驱动并确认；不能把群晖上的网页等同于本机 USB 打印服务。官方接口说明见 [MDN Window.print()](https://developer.mozilla.org/en-US/docs/Web/API/Window/print)，其参数为空，不提供指定打印机参数。本节网页打印面板不额外安装插件、桥接服务，不静默打印，也不嵌入或自动打开 BarTender 设计器；独立 Windows 助手见后文。

打印窗口每页一张标签。较长编码、小标签、热敏浓度及清晰度都影响识读；不能只看预览判断物理可读。

## BarTender 连接 CSV

从单件列表导出 `labos-bartender.csv`，这是 UTF-8 BOM、逗号分隔、双引号包围字段的文本数据库；每行对应一件实物，所有编码保留原文本和前导零。该数据用于 BarTender 的文本数据库连接，**不要双击用 Excel 自动转换或执行内容**。自由文本可能以 `=`、`+` 等字符开头；CSV 按原值提供给打印软件，不插入会改变条码的撇号。业务 Excel 导出另走安全的 XLSX 文本单元格。

1. 在现有 BarTender 设计器中新建标签或打开已有 `.btw`，选择当前已安装的 DL-886A（NEW）驱动，并按实际标签纸设置尺寸。
2. 打开“数据库连接设置”，新增文本文件数据库，选择刚导出的 CSV。设置 UTF-8 编码、逗号分隔、双引号限定、首行为字段名。2016 不同语言／版本的菜单名称可能略有差异；以本机向导为准。
3. 把 `Code` 绑定到 **Code128 条码**对象与编码文本；把 `QRPayload` 绑定到 **QR Code** 对象。不要让 BarTender 给 `Code` 再加前缀或流水号。可只保留所需的一种码。
4. 将其他字段拖到文本对象，设计位置、大小和字体，保存自己的 `.btw` 模板。以后替换为新导出的同名 CSV，刷新连接并预览记录即可复用。
5. 打印时每条选中记录 **1 份**，关闭额外序列化；选择需要的记录。误选多份只会重复标签，不会在业务系统新建实物。

| 字段 | 内容 |
| --- | --- |
| Code | 业务系统已生成的单件固定编码 |
| QRPayload | 系统完整单件二维码内容，按原文绑定 |
| Name / Specification / Unit | 物资名称／规格／单位 |
| CatalogCode | 规范物资主档编码 |
| Region / Warehouse / Location | 归属区域名称／仓库名称／存放位置（较早数据缺少仓库名称时保留原编码） |
| Batch / ExpiryDate / Status | 批号／有效期／单件状态 |

CSV 是导出时的快照，位置或状态变化后需重新导出。打印面板中的“导出 BarTender 数据”导出本窗口加载的全部实物，不受打印起止张范围影响。0.6.0 起继续用 CSV 提供打印数据，配套 Compose 不公开 PostgreSQL 端口给打印软件，也不让 BarTender 修改业务数据库；业务变更仍须经过系统的权限、事务及库存流水。0.5.1 及更早版本使用 `labos.db` 的限制属于历史 SQLite 部署，不能把旧文件连接方式套到当前数据库。0.7.0 仅有网页／CSV；0.8.0 新增下节的独立 Windows 打印助手，未实现 BarTender 命令行路线。

官方参考：[数据库连接与字段拖放](https://help.seagullscientific.com/2022/en/subsystems/gsm/content/GS_User_Databases.htm)、[文本文件编码与分隔设置](https://help.seagullscientific.com/10.1/en/Content/HIDD_DB_WIZARD_ASCII_PAGE.htm)、[打印份数与序列化](https://help.seagullscientific.com/2021/en/Content/Printing_Label_Formats.htm)。官方在线帮助版本不同于本机 2016 R7，本文只复用数据源、字段绑定与记录打印逻辑，不将新版本界面当作本机实测。

## 原生 `.btw` 与直接调用

0.8.0 源码增加原生母版上传、打印站和任务，以及在已登录 Windows 用户会话运行的 PowerShell 7 助手。物资页“BarTender 打印”管理入口及单件列表选件入口按权限显示；手机可建立任务，由连接 USB 的 Windows 助手调用 COM。服务端重新取数建立快照，每件一张，不创建新编码或改变库存。引擎已提交与人工确认分开，超时／断线结果不明不自动重印。

当前0.8.2沿用0.8.1新增的任务纸张覆盖、站点诊断、双击菜单、同用户登录后台和原生模板图预览。PNG由Windows助手生成且不调用Print，网页轮廓实时更新不等于BTW或驱动实时渲染；缩小原生母版需制作匹配尺寸版本，不能复用网页自动缩放规则。新纸张覆盖／预览任务的最低助手协议仍为0.8.1；当前使用同版0.8.2应用与助手。

Windows首次使用先选菜单1检查、2保存初始化配置；这两项及菜单4安装后台均不向LabOS通信或领取。现在处理打印／预览选3并保持窗口打开；需要以后自动运行可先选4，再选3。菜单4只登记，下次该用户登录才后台运行，电脑须开机且用户保持登录。完整操作见[打印助手指南](BARTENDER_AGENT.md)。

0.8.2 Windows助手在本机重新通过Node 3/3（0失败、0跳过）、内部87项与语法检查；Node首项已包含87项，不能重复计数。证据在`artifacts/cache/0.8.2/windows-agent-verification.json`及其引用的报告，仍为模拟引擎验证，没有执行真实COM或USB打印。

助手还提供`-DeriveTemplate`：修改母版已有对象后由`SaveAs()`另存`.btw`，不是任意HTML／JSON转换。命令、字段、权限和恢复见[打印助手指南](BARTENDER_AGENT.md)。0.8.1阶段曾有只读COM诊断，0.8.2未再次启动真实COM；仍无真实模板生成、导出或物理打印证据，实际许可、母版、送料与USB效果仍需现场校准。

最初调研与官方 2016 依据保留在[BarTender 接入分析](BARTENDER_INTEGRATION.md)。其中“尚未接入”是开发前状态，由本节源码实现替代，不代表硬件验收已经通过。`Application.XMLScript()` 在2016要求 Enterprise Automation，本轮采用 COM `Format.Print()`／`SaveAs()`，仍需核实 Automation 或 Enterprise Automation 授权。
