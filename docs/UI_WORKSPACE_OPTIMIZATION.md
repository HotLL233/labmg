# 页面密度与记录工作区优化方案

起草日期：2026-10-23。起草依据：0.12.0源码、用户反馈及静态核查。起草时为**方案与离线HTML原型，尚未修改正式页面**；用户随后批准实施，0.13.0正式源码映射见第8节，实际验证和交付见版本说明。本方案不代表整份A–F业务路线图完成。

参考原型：[打开HTML](prototypes/ui-workspace-compact.html)，可直接用浏览器打开。它使用合成记录演示布局、分页和多级返回，不连接业务API。旧`ui-redesign.html`、`ui-mobile.html`是外部草稿，本轮保留。

## 1. 判断：先改信息结构，再调间距

用户反馈的问题不能靠全局缩小字体解决。主页面有多个标题、说明和工具条，而最需要空间的物资库被放在一个混合维护弹窗的下半段；桌面弹窗又没有套用主页面的紧凑表格规则，因而同时出现“上方空、下面挤”和“少量记录也要下滑”。

| 已核对的位置 | 当前原因 | 产生的现象 |
| --- | --- | --- |
| [app.js:64](../src/public/app.js#L64) | 全局页头、说明、搜索、新建和普通样式的退出并列；侧栏底部只显示服务运行中 | 退出不突出，也没有固定的运行版本和当前账号位置 |
| [server.js:4](../src/server.js#L4)、[material.js:85](../src/public/material.js#L85) | 后端已有package版本常量，但没有返回给页头；物资表单的“版本”实际是记录并发版本 | 不能把“基于单据版本3”当成软件0.12.0版本 |
| [material.js:39](../src/public/material.js#L39)、[material.js:58](../src/public/material.js#L58) | 全局页头、物资模块标题／口号、页签、面板标题、解释、提示、筛选逐层垂直堆叠 | 正文开始得很靠下，按钮和描述比记录更抢空间 |
| [material.js:102](../src/public/material.js#L102) | 分类表、区域标签、库位入口和物资信息库连续放入同一个弹窗；物资查询最多取前200项，没有该视图的真正翻页入口 | 用户要先滚过基础设置才能找到物资，记录多时越来越长 |
| [material.js:111](../src/public/material.js#L111) | 第一列是`编码 / 名称`，编码在上、名称是次级小字；每行并列多项操作 | 读长编码占宽，名称不醒目，操作换行后整行变高 |
| [material.css:1](../src/public/material.css#L1)、[material.css:9](../src/public/material.css#L9) | 弹窗整体`overflow:auto`；头尾固定仅在窄屏规则中覆盖 | 桌面滚动时标题、关闭和底部操作离开视口；重置打开时的滚动位置只能解决一部分问题 |
| [tokens.css:28](../src/public/tokens.css#L28) | 紧凑单元格规则只命中`.page .table`，没有命中body下的物资弹窗；多层`small`继续叠高 | 同一种记录在页面与弹窗中密度不同，看起来忽空忽挤 |
| [material.js:45](../src/public/material.js#L45) | 库存本来已有七列、筛选和分页，但额外分组行、重复名称及行内展开详情会增加高度 | 只有几笔库存也显得很长，展开后相邻记录位置不断变化 |

档案、设备、合同、体系及审计目前已有表格，不能将“记录展示不统一”写成“没有记录功能”。本轮普通UI审计8项通过、0警告、0失败，也说明现有检查**尚不覆盖信息密度、应用版本可见性、滚动次数和关闭按钮是否一直可见**；通过审计不等于这些体验已经合格。

## 2. 统一页面结构

推荐一套页壳：**常驻顶栏 → 当前模块／当前位置 → 当前页签和主操作 → 一条筛选栏 → 记录表 → 分页／状态栏**。同一工作区只保留一个主要标题，不再在每一层重复名称和流程口号。

| 区域 | 建议行为 |
| --- | --- |
| 顶栏 | 常驻LabOS、运行版本、当前账号和醒目的“退出登录”；在二级、三级页面也能看到 |
| 当前位置 | 使用“物资管理 / 物资信息库 / 编辑物资”一类面包屑；返回写清目标，不只显示× |
| 主操作 | 仅当前页高频动作，例如新建、导入／导出；编号、标签和低频维护归设置或更多，不把全部按钮排成几行 |
| 筛选 | 搜索＋2至3个常用条件＋查询／重置；更多条件按需展开，并显示已生效的筛选项 |
| 说明 | 常态保留一句关键业务规则；长说明放“使用说明”，不能默认占一个大色块。错误、权限限制和风险提示仍显著展示 |
| 正文 | 记录表为主，字段、数量和操作对齐。日期／金额／数量用统一格式，名称优先、编码次级 |
| 底部 | 总数、当前页、每页条数／上一页／下一页保持可见；不能只取前200条却没有继续查看的方式 |

运行版本建议由既有`/api/auth/me`响应追加`appVersion`返回，直接复用后端package版本常量；前端不手写0.12.0，也不把镜像名称或单据版本当软件版本。版本读取失败时说明不可用，不能显示一个猜测值。正式实现需要同步服务端响应、启动逻辑与测试。

退出采用有图标和文字的独立按钮，边界与普通操作区分；保持服务端注销会话逻辑。存在未保存输入时先处理离开确认，提交处理中或结果待确认时保留现有保护，不能仅为返回方便丢失输入。

## 3. 物资库与基础设置拆分

物资信息库应成为直接可到达的工作区，不再埋在分类、区域、库位之后。基础设置按“分类 / 归属区域 / 存放库位 / 编号规则”分标签切换，每次只呈现当前一项。

分区只整理已有能力：分类沿用新增及字段类型设置，区域沿用新增；不因画出新页面就默认增加分类／区域改名、启停或删除。物资资料和编号维护继续按既有`manageCatalog`校验（ADMIN或MATERIAL角色，且具备对应权限），不能只看角色或只看单项权限；申报提交、验收和发放仍沿用各自业务权限。

物资表建议列为：**物资名称（次行编码）· 规格 · 单位／管理方式 · 分类 · 状态 · 库存 · 操作**。名称14px并加粗；编码12px、弱化但可完整查看／复制。代码过长可截断显示，完整值在详情和复制中保留。CAS、纯度、SDS等扩展字段进入详情／编辑分区，不全部堆在每个名称单元格内。

每行常显“查看、编辑”，启停、外包装码、管理方式和未引用删除收在“更多”。删除与停用仍按原权限／引用关系受控，不能为简洁隐藏拒绝原因。中文名称继续用于人工选择，内部编码、物资ID和二维码身份不变。

## 4. 各级页面的一屏策略

“一屏显示”以**完整、可读且可操作**为前提，不承诺任意记录量或任意屏幕下无滚动，也不通过`overflow:hidden`裁掉内容。

| 场景 | 布局与滚动规则 |
| --- | --- |
| 桌面1366×768及以上的普通列表 | 标题、筛选、表头和分页在一屏可见；依据正文真实高度与行高取完整行数，剩余记录翻页，不让用户滚整页找分页 |
| 桌面短详情／短表单 | 使用当前完整工作区或适宽面板，双列字段、固定保存／取消／返回。能容纳时整个页面无纵向滚动 |
| 长验收、化学资料、历史修订 | 按业务分区切换，不用多个弹窗互相覆盖；仅当前分区必要时滚动，输入和筛选上下文保留，错误要能定位到对应分区 |
| 记录多、备注很长或浏览器放大 | 允许表体受控滚动或减少每页条数；表头／分页保持可见。长备注进入详情，不能截断后无法访问 |
| 900×650等小窗口 | 自动收拢次要说明、减少每页记录；高度不足时允许正文滚动，不能把字号压小或隐藏操作 |
| 手机 | 同一份表格DOM按CSS重排为有字段名的记录卡，控件至少44px；允许必要的纵向滑动，避免页面整体横向滚动，返回／退出仍可找到 |

沿用现有14px正文、13px表头／标签、12px说明；普通记录行约44px，名称＋编码的双行记录约64px。实际分页必须按可用高度测量，不能把“每页20行”固定后强行塞进768px。长内容的降级是必要条件，不是体验失败。

少量记录不拉高行，不添加虚构统计，也不为了填满屏幕堆装饰卡。表按内容收拢，余下空间保持安静；有实际用途时提供选中记录的只读预览／后续动作。空数据和无匹配分别给“新建／导入”和“清除筛选”入口，不让用户面对一个空白大面板。

## 5. 像Excel的记录展示应做到什么

统一网格线、表头、列对齐、选中行、状态和行操作；列表维持稳定行高，详情不要原地把某一行撑成半页。库存仍优先保留已确认的七列：**入库时间、名称、数量、规格、单位、厂家、备注**；批次／区域／位置与领用、流水放“查看”后的详情分区，原批次管理和记账身份不变。

现有物资合计也须保留，可放在选中记录摘要或物资详情，明确标注“全部仓库／区域合计”，与当前批次数量分别标注。[materials.js:966](../src/materials.js#L966)的`totalQtyM`按物资全部流水汇总，不随搜索、区域、仓库或分页筛选缩小；各行`qtyM`才是对应厂家批次余额。不能把某批数量写成全物资库存，也不能悄悄改变汇总口径。

| 记录类型 | 默认列表重点 | 二／三级工作区 |
| --- | --- | --- |
| 申报 | 标题、次级单号、填报人、日期、项数、状态、操作 | 原单摘要＋明细表；修订历史以时间、办理人、原因的记录表切入前后值 |
| 期初／补录 | 标题、次级单号、登记类型、日期、项数、状态、登记人 | 草稿明细、导入结果及登记原因；入库后查看原单与生成单件，不在历史表中直接改账 |
| 验收待办／进度 | 物资名称、原申报单、申报量、已验收／待验收量、状态、操作 | 保留未验收／部分验收项的办理入口；同一申报明细可有多次验收，不将一行进度当作一笔验收事件 |
| 验收历史事件 | 日期、物资名称、来源原单、合格／拒收数量、金额（有权限）、办理人 | 每次验收独立一行，进入该事件详情、来源原单及冲正记录；与待办／进度分区查看 |
| 领用 | 申请日期、物资、申请人、数量、用途、状态、办理人 | 申请详情、发放记录、具体瓶件，不把全部单件码放在列表格内 |
| 库存／单件 | 七列库存表；单件页突出名称、单件码、状态、位置 | 批次、单件、来源流水切换；返回后保留上一页、查询和选中项 |
| 档案／设备／合同／体系／审计 | 各模块现有核心字段及状态，统一表头／筛选／操作样式 | 短详情可一屏，附件与历史单独分区；保留原访问权限及脱敏 |

这里参考的是Excel的**记录可扫读和列对齐**，不等于直接在单元格修改已入库金额、发放数量或历史流水。行内编辑、任意列设计器和电子表格框架不属于这次布局方案。

## 7. 验收标准与本轮证据

- 1366×768、1440×900：版本／账号／退出始终可见；普通列表可完整看到筛选、首屏记录和分页；三级详情可明确返回，短表单保存／取消在视口内。
- 900×650、768×1024、390×844：没有内容被裁掉，手机无页面级横向溢出；必要纵向滚动不影响操作。放大与长错误不得被强制裁切。
- 搜索、筛选、分页、返回上下文、空状态、长编码／名称／备注均可复核；历史单据及库存数量不因布局而变化。
- 普通与严格UI审计都要通过，但增加本方案专属的浏览器几何和交互断言；不能仅凭原8项审计宣称布局问题已修复。

本轮实际检查：

- 真实Edge离线原型检查368项通过、0脚本异常、0网络请求，27张截图；完整覆盖1366×768、1440×900、900×650、768×1024、390×844，另对1366×480仅检查降级后分页、表单末字段和保存可达，不宣称该高度无滚动。
- 1366×768物资表可完整显示6条名称＋编码双行记录，筛选／表头／分页同屏；38条合成记录均可通过分页查看。检查了六个业务入口、四类设置、搜索与无结果恢复、三级返回、未保存离开确认、更多菜单可见及手机滚动焦点。
- 原型切换编辑页签时提示放弃未保存输入；正式实现仍建议保存分区草稿，不能将原型的确认简化视作草稿持久化。原型保存、退出、导入、扫码等只演示入口或反馈，不执行真实操作。
- root复读最终报告并目视桌面物资表、窄窗口编号保存区、手机编辑／滚动焦点及低高度末字段截图。普通和严格生产UI审计均8通过／0警告／0失败，方案13个本地文件／行号引用及HTML内联脚本语法检查通过；它们的覆盖范围分别记录，不相互替代。

最终证据：`artifacts/cache/0.12.0/ui-workspace-design/edge-peWl4j/report.json`，复查脚本为同缓存目录的`check-prototype.cjs`。首轮170项通过后仍发现重复页头与保存区体验问题，已在原型中调整；中间一次“900px应同页显示全部3条”的检查假设不成立，修正为按实际空间分页后再检查，保留原报告。

原型演示与静态核查不等于正式业务、群晖、真实手机相机、USB打印或全量回归验收。未验证真实浏览器缩放、软键盘及其他浏览器；后续正式施工须按以上验收标准补齐生产界面与实际API测试。

## 8. 正式实施映射（0.13.0，2026-10-23）

用户随后批准按此方案改造。以下是正式源码的实施映射，补充上文“仅方案”的历史阶段；是否完成验证及公开交付，以[版本说明](CHANGELOG.md)的最新记录为准。

| 阶段 | 正式实现 | 保留的边界 |
| --- | --- | --- |
| W1 | 会话接口返回package版本；页头与详情常驻版本、账号和退出；搜索／新建移入业务工具栏；新增共享工作区及完整已加载表格的客户端分页 | 真实注销、权限和并发保护沿用原接口；已有服务端分页不重复切页；未保存先确认，保存／上传中禁止离开 |
| W2 | 物资信息库独立入口，名称主显、编码次显，使用真实服务端分页；分类、区域、库位、编号分标签 | 中文输入、资料编辑／启停／引用删除、Excel与现有管理权限保留；不增加区域改名等业务 |
| W3 | 库存七列保留，详情移出行内；多级返回恢复查询、页码与父工作区；验收进度与历史事件分区 | 全部仓库／区域合计与当前批次数量分别显示；历史事件接口没有筛选参数，页面不提供无效筛选；原流水、金额脱敏、二维码和标签校准保持 |
