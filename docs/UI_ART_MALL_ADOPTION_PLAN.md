## 1. 结论与证据边界

重点分析用户指定的 Art Design Pro X 商城入库管理，服务于 LabOS 的申报、验收和库存页面。推荐方向是：

**借鉴后台表格页的组织方式，保留 LabOS 的实验室业务、原生前端和现有状态保护。**

当前已核实：

- 指定地址访问后跳转到登录页，并出现验证码。未读取或填写账号密码，未处理验证码、提交登录或发起业务写入。因此**没有看到实际入库管理页面**，不能给它的列数、列宽、统计卡、默认筛选和详情形式下实测结论。
- 官方另列的纯前端演示也跳转登录页，并要求滑块验证；未操作验证或登录，不能用另一个站点冒充指定页面实测。
- 官方资料把该在线站点列为 NestJS 版演示。公开仓库本轮固定为 `Daymychen/art-design-pro` 的提交 `f3aaf58eec1a0e988f162352c33862327a484f95`，提交时间为 2026-06-01；该树中没有 `src/views/mall` 或入库管理页面。不能把公开基础版组件当成商城模块源码。
- 已只读检查该提交的 20 份基础组件、页面和配置文件。通用搜索区、表格工具栏、分页、菜单和页面容器可以作为设计依据；这不代表在线商城页面逐项采用同一实现。
- LabOS 当前正式代码为 `0.14.9`，Node 原生 HTTP、PostgreSQL、原生 JS/CSS，无 React/Vue 构建链。本轮不更换技术栈、不修改业务版本、发布资产或 NAS。

## 2. 已核实、可借鉴的通用做法

| 上游依据 | 借鉴点 | LabOS 的取舍 |
| --- | --- | --- |
| `art-search-bar` | 可见字段标签、查询／重置、折叠高级条件、响应式表单排列 | 常用条件优先；日期、区域、仓库按需展开；显示已生效条件，不把输入框平均拉满 |
| `art-table-header` | 本页主要动作与表格辅助工具分开 | 左侧标题／结果数，右侧主要动作与本页更多；模块工具另有明确归属 |
| `art-table` | 结果、加载态、空态与分页统一组织 | 复用已有 `Workspace` 和物资分页，保持稳定 10／20／50；不重复切片服务端结果 |
| 侧栏、顶栏、面包屑 | 当前模块和当前位置清楚，导航与业务内容分层 | 保留一套全局账号与退出；单侧栏＋模块页签，不新增第二列常驻业务菜单 |
| 用户管理示例页 | 搜索、列表、行操作、编辑窗口的职责清楚 | 只借排版；本地继续调用真实权限、并发版本、审计和业务接口 |

上游需要谨慎对待的部分：

- `art-table-header` 的右侧工具区带小屏隐藏样式。LabOS 手机端必须保留筛选、导出及其他唯一功能入口，可收进菜单，不能直接隐藏。
- 上游有列显示／拖动、密度、全屏等通用工具。第一批不全量复制；库存七个业务字段、验收八列以及关键厂家／位置字段不能变成可随意隐藏项。
- `art-work-tab` 和 `KeepAlive` 有多标签及缓存机制。暂不引入，避免与 LabOS 的未保存、忙态、未知结果和三级返回保护冲突。
- 上游表格高度有按容器计算的机制。LabOS 少量记录应自然结束，不用大空白表体填满屏幕，不恢复按行高自动重请求分页。
- 上游用户页的删除示例以确认框、日志和成功提示演示，不能据此推断真实删除接口；通知组件也有本地示例数组。不能把这些样例等同于 LabOS 的真实业务能力。

以上只界定所读基础版示例的证据范围，不是对在线商业版商城后端能力的评测。

## 3. 商城概念与本地功能的映射

下面是**本地适配规则**，不是对尚未访问的商城页面所作描述。

| 如上游存在这类结构 | 对应 LabOS | 必须保留的本地含义 |
| --- | --- | --- |
| 单据列表 | 物资申报列表 | 主题、单号、创建人、日期、申报状态和验收进度分层，不能混成一个状态 |
| 入库单及商品明细 | 按申报单分次验收 | 原申报／修订上下文、剩余量、本次合格数量、实付总额、厂家和位置 |
| 商品／SKU | 物资名称、编码、规格、单位及管理方式 | 不新增商品规格体系，不允许验收时静默更换已锁定单位或物资身份 |
| 仓库／供应商 | 本地仓库、归属区域、厂家等既有字段 | 厂家不等于供应商；不能为照搬排版而改字段语义或扩展业务模型 |
| 批量操作 | 现有批量原子验收 | 沿用服务端事务、幂等键及原请求体，不以循环单行提交冒充整批事务 |

| 出库办理 | 领用申请与管理员发放 | 申请不预占／扣减库存，管理员发放才记账，不能改成点按钮即出库 |
| 详情与记录 | 物资详情、批次／单件、来源流水 | 保留同一物资上下文、权限和三级返回，不用通用商品抽屉替换全部记录 |

## 4. 建议的本地页面骨架

以下为 **LabOS 建议稿，不是商城页面截图还原**。

```text
全局头：物资管理 / 验收                         账号 · 版本 · 退出
业务入口：申报 | 验收 | 库存                    物资设置 / 模块工具

按单验收                                       本页必要动作
搜索与常用条件                         高级筛选 / 当前条件 / 清除

当前申报单主题
单号 · 修订 · 创建人                            切换申报单 / 原单
办理验收 | 到货清单 | 验收历史

选择 | 名称规格 | 申报进度 | 本次合格 | 实付总额 | 厂家位置 | 状态 | 操作

已选 N 项                          取消／返回 | 选中项入库 | 整单待验项
```

### 4.1 导航与顶部

- 延续当前桌面侧栏和窄屏图标栏基线；商城侧栏的宽度待截图比较，不预先认定上游宽度更合适。
- 顶栏只放当前位置及全局账号，不堆放全屏、换肤、语言、锁屏、消息等不属于本轮的入口。
- 物资三个主入口保持一处；不再叠加一排“已打开页面标签”。
- 面包屑返回也经过原有离开保护，不能绕过未保存或未知结果锁。

### 4.2 搜索与工具栏

- 默认只显示名称／单号搜索和最常用状态；区域、仓库、日期放高级条件。
- 所有日期范围有可见起止标签；已生效条件可见且可清除。
- 短字段按内容设宽，搜索吸收余宽；不为整齐把所有输入拉成等宽大框。
- 一页只突出一个当前主要动作；导出、模板等低频动作进入明确的“本页动作”菜单。
- 排序若缺少对应服务端查询能力，先不加入，不能把当前页排序展示成全量排序。

### 4.3 列表密度与字段层级

- 页面标题 22px、区块 18px、正文 14px、标签 13px、说明 12px，沿用现有令牌，字距为 0。
- 单号／编码作为名称下方次级信息；名称不全站统一截断。操作靠近对象身份，不单独推到长行底部。
- 数量右对齐、使用等宽数字；手机左对齐。不同单位不能随意合成一个“总数量”。
- 状态保留真实文字和有限语义色，不靠颜色单独表达。
- 库存维持入库时间、名称、数量、规格、单位、厂家、备注七个业务字段；备注允许摘要和全文展开，打印及导出保留全文。
- 小圆角 6–8px、轻边界、少量状态色；不为填空增加统计卡、商品图片墙或多层卡片。

### 4.4 验收办理区

- 选单按需打开，编辑区占完整业务宽度；不恢复常驻 220–272px 选单栏。
- “申报进度”优先显示“剩余 X 单位”，申报／已验／结案分别完整标注，不用四值斜杠让用户猜顺序。
- 金额、厂家、位置常驻；批次、效期、差异按需展开，不藏掉核对必需信息。
- 本次验收成功后留在当前单据，更新真实进度；到货资料在独立分区办理，不挤占主表。
- 确定失败、冲突、成功、结果待确认分别反馈；未知结果只沿用原正文／原幂等键，不盲目第二次新增。
- 底部提交区在低高度可滚动到达，不能遮挡末行字段。

### 4.5 详情、手机和打印

- 普通详情保持 1120px、短表单 760px、设置内容 1040px 的现有上限；宽表和验收继续按任务需要全宽。
- 详情使用少量局部页签，不把只读资料、编辑和审核动作混在每个字段卡片里。
- 手机使用同一份 DOM 转卡片／编辑网格，名称、数量、单位优先，操作至少 44px。
- 筛选、导出、切单、资料和保存都必须能在手机上找到，不照搬小屏隐藏工具栏。
- 原单 A4、二维码、标签纸与已有打印校准保持各自作用域，不受屏幕风格改动影响。

## 5. 与其他本地模块的关系

商城列表模式可以逐步扩展，但不在第一批顺手重做全部模块。

| 本地模块 | 可沿用的组织方式 | 需防止的误改 |
| --- | --- | --- |
| 档案、体系文件、合同、人员 | 搜索＋分区／状态＋结果表；详情内版本和附件分组 | 不能删掉角色范围、受控版本、有效期或金额权限 |
| 设备 | 阶段筛选、紧凑统计、清楚的附件记录 | 当前拼装的建档／当前阶段信息不等于完整历史事件库，不能凭排版虚构完整时间线 |
| 账号与角色 | 左侧角色、右侧按模块分组的权限表单 | 折叠／过滤应保留原 checkbox 状态；只渲染一部分再整包保存会有丢失未显示授权的风险，须单独验证 |
| 导出、备份、审计 | 清楚区分主要动作、辅助动作和危险操作 | 不替换既有 CSV/XLSX、完整备份脚本、恢复权限及审计逻辑 |
| 工作台 | 少量可下钻的真实待办 | 不复制商城销售图表或示例通知数组，不编造未接接口的数字 |

工作台若进入下一批，须另行核对数据口径：当前 `/api/dashboard` 是通用记录聚合，不能直接把它的 `materials` 记录数当成新版物资库存或待验收数量；待验收、待发放、批次临期等指标需要对应真实查询和权限过滤。这不是纯 CSS 改动。

## 7. 验收标准

这些是**后续实施要求，不是本轮已通过结果**。

- 在 1920、1440、1366、1093、900、768、390、360px 及 1366×480 低高度检查，等效 CSS 视口不冒充原生缩放。
