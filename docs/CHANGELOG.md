# 版本更新说明

本文件是项目统一的版本更新记录。以后新版本在本文件中新增，按新版本在前排列，保留所有历史版本；不要另建每个版本的说明文件。

开发中的变更先加入“未发布”。实际发布时新增真实版本号与日期，将对应内容归入该版本，并同步 `package.json`、Git 标签和相关文档。版本条目记录功能变化、修复、兼容性或数据迁移影响及验证结果；未执行的验证须如实说明。

## 0.2.0-rc.1（2026-10-16，第一轮首个候选版）

### 数据、权限和多人编辑

- 移除启动时永久删除旧 `samples` 记录、附件索引和旧权限的逻辑，旧业务入口仅隐藏。
- 统一记录、附件、导出、备份、统计、回收站及模板导入的模块、分区和档案角色范围校验；写入和删除同时要求可读取对应记录。
- 新建、重置和导入账号使用带盐 scrypt；兼容旧明文账号并在成功登录后升级，备份输出旧密码的哈希快照。退出撤销会话并正确清 Cookie，改密撤销该用户已有会话。
- 完整备份的账号/角色内容额外要求权限管理读取授权；恢复这些内容额外要求权限管理写入授权。恢复失败回滚新记录并清理新写附件，避免恢复接口绕过账号权限。
- 增加记录整数 `version` 和条件更新。过期编辑返回 409；软删除、恢复和体系文件当前版本联动也递增版本，避免旧表单覆盖新修改。

### 页面

- 统一页面导航、公共记录状态和加载流程，修复查看/编辑找不到记录、新建归错模块、搜索及删除后刷新错误。
- 修复设备阶段中英文值匹配；旧列表响应不再覆盖新页面。
- 根据登录返回的有效权限隐藏无权访问的模块和管理动作；非管理员新建档案默认带自身角色范围。
- 补齐模板、人员的分区选择及财务预算选项；仅授权部分分区时严格限制，全部已知分区授权保持全模块范围，默认经理可维护未分类历史记录。
- 编辑冲突时保留输入和持续错误提示，提供明确放弃输入后重载的操作；补充本轮触及的表单、物资及账号显示转义。

### 版本隔离与构建缓存

- 功能分支 `feature/v0.2.0-round1` 承载本轮开发，候选版集成到 `develop`；稳定 `main` 继续保留 `0.1.1`。
- 开发数据改为 `var/development/<version>/`，普通运行仍使用 `var/`；不会自动搬入旧版本开发数据。
- 统一生成 `artifacts/releases/<version>/labos-<version>.zip` 和 `manifest.json`，清单包含构建提交、源码摘要、ZIP 大小与 SHA-256。
- 构建、测试、解压验证副本集中于 `artifacts/cache/<version>/`；同版同内容并校验通过才复用，同版变化或损坏拒绝覆盖，历史版本产物保留。
- 原 0.1.1 包和验证目录归档到新的版本目录，不重打历史包，不补造历史清单。

### 文档与验证范围

- 新增 `MEMORY.md`，汇总可见会话中的历史需求、项目事实、决策、已知问题、验证范围和后续计划，并约定持续记录新记忆。
- 新增 `HISTORY.md`，按事件顺序保留开发过程、提交、版本整理和验证依据。
- 增加仓库维护入口，在开发说明与 README 中链接上述记录，统一后续维护规则。
- `npm run check` 通过全部 15 个 JavaScript 文件；`npm test` 的 18 项回归全部通过，包含 8 组隔离后端权限/会话/冲突检查、8 项前端 VM 检查、版本化打包及三种运行模式冒烟。打包回归覆盖清单/ZIP 校验、同版复用、拒绝覆盖、排除敏感文件和升版保留旧产物。

兼容性：首次启动会为旧记录补充版本列并更新体系文件联动触发器。旧客户端 PUT 必须带读取到的整数 `version`，缺失返回 400。上线前应停服备份完整运行目录，在独立副本验证数据；本轮回归使用隔离副本，没有升级真实运行数据库。

本版仍是候选版。尚未做真实浏览器交互和布局验收、30 人混合负载压测及完整灾备演练。保留 SQLite 与本地附件，设备附件逐条统计、同步重操作、分页及业务事务完整性仍需后续开发；旧账号未登录前仍可能保留旧明文，旧备份不会自动改写。

## 0.1.1

- 将服务端和静态前端整理到 `src/`，检查与打包脚本整理到 `scripts/`。
- 将环境变量示例移到 `config/`，Docker 配置移到 `deploy/`，增加开发和版本说明。
- 本地数据库、附件和日志统一放在忽略提交的 `var/`；开发模式默认使用独立的 `var/development` 和 3001 端口。
- 通过 `LABOS_RUNTIME_DIR` 指定运行根目录；环境变量示例不自动加载。
- 扩展语法检查范围至全部 JavaScript；部署包输出到 `artifacts/labos-0.1.1.zip`，并保留整理后的目录结构。
- 约定 `main` 为稳定分支、`develop` 为开发分支、`feature/*` 为功能分支；以 `v0.1.1` 标记整理版。

本版是项目组织与运行目录调整，不包含已知权限、密码存储或并发业务问题的修复，也不改变当前 SQLite 与本地附件的存储方案。
